# 修復例：欠損と読み取り誤りを含むQRコード

[English](README.md) | 日本語

| 修復前 | 修復後 | 修復箇所 |
| --- | --- | --- |
| ![欠損セルと2ビットの誤り](before.png) | ![修復後のQR](after.png) | ![補完セルは青、訂正セルはオレンジ](details.png) |

独自に生成したこのQRには、441セル中53セル（12.0%）の欠損と、既知のデータセルに2ビットの誤りがあります。誤り上限が初期値の5%の場合、[記録された結果](result.json)では次の2候補が得られます。

```text
QRevy repaired.
QBefy repair`d.
```

最初の候補は既知の2ビットを変更し、すべてのセルが元のQRに一致します。もう一方は既知の6ビットを変更します。掲載画像は最初の候補です。修復箇所の画像では、補完した53セルを青、訂正した既知の2セルをオレンジで示しています。既知セルの訂正位置は20列・10行と18列・17行です。誤り訂正とQR構造検証の成功だけでは正しい候補を確定できません。

## 試す手順

1. **テキスト行列を読み込む**で[before.txt](before.txt)を開きます。簡易自動修復の処理中や失敗時は**詳細解析へ**、候補が見つかっていたら**詳しく解析する**を選びます。
2. **単一セグメントの終端後構造を強制する**をONにし、記入済みの`*`を保ちます。四角い位置検出パターン（Finder）の役割を確認してください。バージョンは入力から決まる1で、**ECC: 自動**と**mask: 自動**は変更しません。
3. クラッシックでは**設定を保存して修復**、モダンでは**修復**を選び、得られた候補を比較します。

QRの誤り訂正符号（**ECC: Error Correction Code**）には、**リード・ソロモン（RS: Reed–Solomon）符号**を使います。コード語（語）は8ビットのまとまりで、RSブロックはまとめて訂正するコード語のグループです。修復後のQRはECC L・マスク0です。それ以外の探索設定は初期値のままです。

| 設定 | 値 |
| --- | --- |
| 形式情報の誤り上限 | 初期設定（6ビット） |
| データ・ECCの誤り上限 | 初期設定（5%の切り上げ、バージョン1では11ビット） |
| 優先探索のセル数上限 | 4（この入力で使うのは1セル） |
| 部分bit探索・自由度の上限 | 12ビット |
| 通常RSからの追加探索上限 | ＋1語／RSブロック |
| 既知bit誤りの追加探索 | OFF |

[before.png](before.png)を画像として読み込み、手順1と同様に詳細解析へ進むこともできます。閾値の自動設定と初期化された外周・バージョン・向きを保ちます。セル編集を開き、最下段の右端から2番目のセル（1から数えて20列・21行）を選び、`*`を指定してください。**単一セグメントの終端後構造を強制する**をONにし、必要ならFinderの役割を確認して修復を実行します。操作は[ユーザーガイド](../../USER_GUIDE.ja.md)を参照してください。

## 別の操作手順：既知bit誤りの追加探索

テキスト行列を読み込み、手順1と同様に詳細解析へ進みます。**単一セグメントの終端後構造を強制する**はOFFにしたまま、**詳細設定**で**既知bit誤りの追加探索: 最大2bit**を選びます。記入済みの`*`はそのままでかまいません。**データ・ECCの誤り上限**は「初期設定」（バージョン1では11ビット）のままにして修復を実行します。

終端後構造の強制なしで、元のQRと一致し、`QRevy repaired.`を含む候補が得られます。候補は一意ではなく、`QBefY repaired.y`という別のテキスト候補に加え、文字列を復号できない候補も得られます。誤り訂正の成功だけでは正しい内容を確定できないため、候補を比較してください。

## この設定で使われる修復方法

優先探索セルは、内容の符号化方式を示すモード指示子の不明な1ビットです。仮置きにより単一セグメントの終端後構造の強制を適用できるようになります。この値は画像の観測ではなく仮説です。強制により、終端・バイト境界合わせ・埋め草の欠損20ビットを補完します。その後もECCの4語が丸ごと不明で、内容を表すデータの2語にはそれぞれ1ビットの誤りが残ります。通常の誤り・消失RS訂正に必要なECCは`2 × 2 + 4 = 8`語となり、このQRの7語を超えます。

リスト復号は、通常のRS訂正の範囲を超えて候補を探す方法です。この例では、Wu法が通常の訂正半径1語から1語広げた2語で、初期値の11ビットの誤り上限を守りながら元のQRを復元します。訂正半径は、消失として扱う語を除き、その計算で使った値と異なってよいコード語数の上限です。各方法は[修復戦略](../../RECOVERY_STRATEGY.ja.md)を参照してください。

### 比較結果

**既知bit誤りの追加探索**をOFFにし、同じ入力と初期値の探索上限で詳細解析を実行した結果です。

| 条件 | テキスト行列の候補 | 画像の候補 |
| --- | --- | --- |
| 優先探索＋単一セグメントの終端後構造の強制＋リスト復号 | 元と一致する候補を含む2件 | 元と一致する候補を含む2件 |
| 単一セグメントの終端後構造の強制OFF | 文字列復号なし・元と一致しない5件 | 文字列復号なし・元と一致しない5件 |
| リスト復号の段階を意図的に無効化 | 0件 | 0件 |
| 優先探索の指定を解除 | 0件 | 0件 |

**単一セグメントの終端後構造を強制する**がOFFの5候補は、いずれもQR構造検証を通りますが、文字列の復号には成功せず、元のQRとも一致しません。[結果の記録](result.json)では構造検証と文字列復号の件数を区別し、データの全バイト列と訂正記録も掲載しています。

### 既知bit誤りの追加探索

この手順では、既知ビットの誤り位置を探索し、RSのビット制約を解きます。入力には不明ビットを含むコード語が8語あり、ECCの7語を超えるため、通常の誤り・消失RS訂正だけでは復元できません。既知bit誤りの追加探索を有効にすると、リスト復号をOFFにしても元のQRに一致する候補が得られます。`*`を残しても解除しても同じ結果です。

掲載画像、結果ファイル、上の比較表は、既知bit誤りの追加探索をOFFにした、優先探索とリスト復号を使う手順の記録です。別の操作手順の測定結果ではありません。
