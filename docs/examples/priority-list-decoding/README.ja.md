独自に生成したこのQRには、441セル中53セル（12.0%）の欠損と、既知のデータセルに2bitの誤りがあります。[記録された結果](result.json)では、すべてのセルが元のQRに一致する候補が1つ得られ、次のテキストを復元できました。

```text
QRevy repaired.
```

修復箇所の画像では、補完した53セルを青、訂正した既知の2セルをオレンジで示しています。既知セルの訂正位置は20列・10行と18列・17行です。

## 試す手順

「テキスト行列を読み込む」で[before.txt](before.txt)を開き、**単一セグメントの終端後構造を強制する**をONにします。記入済みの`*`を保ち、Finderの役割を確認して「修復」を実行してください。バージョンは入力から決まる1です。ECC・マスクは自動のままにします。修復後のQRはECC L・マスク0です。

それ以外の探索設定は初期値のままです。

| 設定 | 値 |
| --- | --- |
| フォーマットbitの誤り上限 | 初期設定（6bit） |
| データ・ECCの誤り上限 | 初期設定（バージョン1では2bit） |
| 優先探索のセル数上限 | 4（この入力で使うのは1セル） |
| 部分bit探索・自由度の上限 | 12bit |
| 通常RSからの追加探索上限 | ＋1語／RSブロック |
| 既知bit誤りの追加探索 | OFF |

[before.png](before.png)を画像として読み込むこともできます。しきい値の自動設定と初期化された外周・バージョン・向きを保ちます。「セル編集」で、最下段の右端から2番目のセル（1から数えて20列・21行）を選び、`*`を指定してください。**単一セグメントの終端後構造を強制する**をONにし、必要ならFinderの役割を確認して「修復」を実行します。操作は[ユーザーガイド](../../USER_GUIDE.ja.md)を参照してください。

## 三つの方法が必要な理由

優先探索セルは、種類を示すヘッダーの不明な1bitです。仮置きにより単一セグメントの終端後構造の強制を適用できるようになります。この値は画像の観測ではなく仮説です。強制により、終端・境界合わせ・パディングの欠損20bitを補完します。その後もECCの4語が丸ごと不明で、ペイロードの2語にはそれぞれ1bitの誤りが残ります。通常の誤り・消失RS訂正に必要なECCは`2 × 2 + 4 = 8`語となり、このQRの7語を超えます。Wuリスト復号は、通常の半径1から1語広げた半径2で、既定の2bitの誤り上限を守りながら元のQRを復元します。

## 別の操作手順：既知bit誤りの追加探索（2026.10.30追記）

テキスト行列を読み込み、**単一セグメントの終端後構造を強制する**はOFFにしたまま、詳細設定で**既知bit誤りの追加探索：最大2bit**を選びます。記入済みの `*` はそのままでかまいません。既知データ・ECCの不一致上限は、既定値の「初期設定」（バージョン1では2bit）のままにします。「修復」を実行すると、終端後構造の強制なしで、元のQRと一致し、`QRevy repaired.` を含む候補が得られます。

この手順では、既知bitの誤り位置を探索し、RSのビット制約を解きます。入力には不明bitを含むコード語が8語あり、ECCの7語を超えるため、通常の誤り・消失RS訂正だけでは復元できません。既知bit誤りの追加探索を有効にすると、リスト復号を無効にしても元のQRに一致する候補が得られます。`*` を残しても解除しても同じ結果です。

候補は一意ではなく、`QBefY repaired.y` という別のテキスト候補も得られます。誤り訂正の成功だけでは正しい内容を確定できないため、候補を比較してください。

掲載画像、結果JSON、上の比較表は、既知bit誤りの追加探索をOFFにした、優先探索とリスト復号を使う手順の記録です。この別手順の測定結果ではありません。
