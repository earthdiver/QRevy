# 修復例：穴があいたQRコード

[English](README.md) | 日本語

| 修復前 | 修復後 | 補完・訂正箇所 |
| --- | --- | --- |
| ![不規則な穴と黒い損傷がある合成QR](before.png) | ![修復後のQR](after.png) | ![補完を青色、訂正をオレンジ色で表示](details.png) |

正常なQR画像に穴と縁の黒い損傷を加えた合成例です。841セル中503セル（59.8%）が消失しています。青色は補完したセル、オレンジ色は黒い損傷を訂正した1セルです。

単一セグメントの終端後構造の強制と1ビットの優先探索で、元のQRコードと一致する候補が1件得られます。復号される全文は次のとおりです。

```text
QRevy app: recovered QR.
```

## 試す手順

1. [before.png](before.png)を画像として読み込みます。簡易自動修復の処理中や失敗時は**詳細解析へ**、候補が見つかっていたら**詳しく解析する**を選びます。
2. バージョンを3（29×29セル）に合わせ、格子の四隅と向きを確認します。この例では、四隅を手動で確認・指定してください。画像は888×888pxで、角セルの中心座標は左上 `(108, 108)`、右上 `(780, 108)`、右下 `(780, 780)`、左下 `(108, 780)` です。
3. 閾値は自動のままにします。下表の62セルに値を入力し、**仮指定（訂正可）**を選びます。残りの503個の不明セルは`?`のままにします。
4. **29行29列**の不明セルに`*`を指定し、優先探索の対象にします。優先探索のセル数上限は初期値の4セルのままで足ります。
5. **単一セグメントの終端後構造を強制する**はOFFのまま、クラッシックでは**設定を保存して修復**、モダンでは**修復**を選びます。最初の探索では候補は0件で、再実行が提案されます。
6. **「今回だけ再実行」**を選びます。元のQRと一致する候補が1件得られます。

あらかじめ**単一セグメントの終端後構造を強制する**を手動でONにして修復を実行しても、同じQRが得られます。以下は、詳細解析で「今回だけ再実行」を選ぶ場合の設定です。

QRの誤り訂正符号（**ECC: Error Correction Code**）には、**リード・ソロモン（RS: Reed–Solomon）符号**を使います。コード語（語）は8ビットのまとまりで、RSブロックはまとめて訂正するコード語のグループです。

| 修復設定 | 値 |
| --- | --- |
| 単一セグメントの終端後構造を強制する | **OFF** |
| ECCレベル・データマスク | 自動 |
| 白黒の閾値 | 自動（この格子では黒4以下・白229以上） |
| 形式情報の誤り上限 | 初期設定（6ビット） |
| データ・ECCの誤り上限 | 初期設定（5%の切り上げ、28ビット） |
| 優先探索のセル数上限 | 初期値（4セル） |
| 部分bit探索・自由度の上限 | 初期値（12ビット） |
| 通常RSからの追加探索上限 | 初期値（＋1語／RSブロック） |
| 既知bit誤りの追加探索 | 初期値（OFF） |

操作の詳細は[ユーザーガイド](../../USER_GUIDE.ja.md)を参照してください。

### 検証条件

消失セルと仮指定の値は、損傷画像から判定しています。セルを3×3に分割した9個の中心点すべてが灰色の穴に含まれる場合を消失とします。優先指定したセルは、内容の符号化方式を示すモード指示子の先頭ビットです。

通常RSと、初期値の上限12ビットで仮置きを試す通常RSでは復号できず、部分ビット制約で復号します。正しい優先割当と終端後構造の強制の後も35語が消失し、通常RSの容量26語まで減らすには最低14ビットの仮置きが必要です。各方法は[修復戦略](../../RECOVERY_STRATEGY.ja.md)を参照してください。
