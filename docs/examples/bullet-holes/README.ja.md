# 修復例：穴があいたQRコード

[English](README.md) | 日本語

| 修復前 | 修復後 | 補完・訂正箇所 |
| --- | --- | --- |
| ![不規則な穴と黒い損傷がある合成QR](before.png) | ![修復後のQR](after.png) | ![補完を青色、訂正をオレンジ色で表示](details.png) |

この画像先行の合成例では、841セル中503セル（59.8%）が消失しています。正常なQR画像に穴と縁の黒い損傷を描き、その画像から消失セルと仮固定の値を判定しています。セルを3×3に分割した9個の中心点すべてが灰色の穴に含まれる場合を消失とします。青色は補完したセル、オレンジ色は黒い損傷を訂正した1セルです。

単一セグメント仮定と1bitの優先探索で、元のQRコードと一致する候補が1つ得られます。復元される全文は次のとおりです。

```text
QRevy app: recovered QR.
```

## 試す手順

1. [before.png](before.png)を画像として読み込みます。
2. バージョンを3（29×29セル）に合わせ、格子の四隅と向きを確認します。この例では、四隅を手動で確認・指定してください。画像は888×888pxで、角セルの中心座標は左上 `(108, 108)`、右上 `(780, 108)`、右下 `(780, 780)`、左下 `(108, 780)` です。
3. 閾値は自動のままにします。9個の中心点すべてが穴に含まれる503セルは不明のまま保ちます。それ以外で自動判定が `?` になった62セルを、下表のとおり画像に残る白黒に従って**仮固定**します。
4. **29行29列**の不明セルを優先探索に指定します。モード指示子の先頭1bitに当たります。優先探索の上限は既定の4bitのままで足ります。
5. **単一セグメントの仮定**をONにし、「修復」を実行します。候補は1件です。

| 修復前設定 | 値 |
| --- | --- |
| 単一セグメントの仮定 | **ON（既定からの変更）** |
| 誤り訂正（ECC）レベル・データマスク | 自動 |
| 白黒の閾値 | 自動（この格子では黒4以下・白229以上） |
| フォーマットbitの誤り上限 | 既定（6bit） |
| データ・ECCの誤り上限 | 既定（5bit） |
| 優先探索のセル数上限 | 既定（4bit） |
| 部分bit探索・自由度の上限 | 既定（12bit） |
| リスト復号の追加誤り上限 | 既定（1個） |

操作の詳細は[ユーザーガイド](../../USER_GUIDE.ja.md)を参照してください。

### 比較結果

| 条件 | 候補数 |
| --- | --- |
| 単一セグメント仮定ON・優先探索あり | 元と一致する1候補 |
| 単一セグメント仮定OFF・優先探索あり | 0 |
| 単一セグメント仮定ON・優先探索なし | 0 |

通常RSと、既定12bitの仮置きあり通常RSでは復号できず、部分bit制約で復号します。正しい優先割当と仮定による補完の後も35語が消失し、通常RSの容量26語まで減らすには最低14bitの仮置きが必要です。
