# QR Repairユーザーガイド

[English](USER_GUIDE.en.md) | 日本語

このガイドは、Android版QR Repairで損傷QRを読み込み、調整、修復、確認、保存するまでの操作を説明します。内部アルゴリズムは[修復戦略](RECOVERY_STRATEGY.ja.md)、各診断項目は[修復結果情報の読み方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

修復結果は元の内容と同一であることを保証しません。URL、認証情報、送金先など重要な内容は、別の資料や手段でも確認してください。

## 1. 入力する

| 入力方法 | 向いている状況 | 注意点 |
| --- | --- | --- |
| 画像ファイル | 既に撮影・スキャンした画像がある | EXIF方向を適用して読み込む |
| カメラ | その場で撮影する | 撮影後にクロップを確定する。一時JPEGは読込み後に削除する |
| `0 / 1 / ? / *`行列テキスト | セル判定を別手段で用意した | 許可された文字と正しいQR寸法だけを受け付ける |

画像には、QR全体と可能なら周囲の余白が入り、各セル中心がつぶれすぎていないものを使用します。機密QR画像を公開Issueへ添付しないでください。

## 2. 画像と幾何を調整する

1. 必要に応じて90°、1°、0.1°単位で回転します。
2. QRの範囲へクロップを合わせます。
3. 自動推定された四隅とバージョンを確認します。
4. 黒／不明／白の閾値を確認し、灰色損傷を`?`として残す範囲を調整します。
5. 色付き損傷を不明領域として使う場合だけ「自動検出された色クラスタを不明領域（?）として扱う」をONにします。初期値はOFFです。

自動推定値は開始値であり、正しいQRであることの証明ではありません。四隅は外周モジュールの中心へ合わせ、選択バージョンと一辺のセル数が整合することを確認します。

新規画像の四隅とバージョンは、ZXing-C++、格子周期、2つのFinderを使う補助推定の順に試します。最後の方式はバージョン2以上が対象です。対角の2つのFinderと横・縦のタイミングパターンを十分に照合できれば、位置合わせパターンがなくても右上・左下を自動設定します。照合が不十分でも、右下の位置合わせパターンが確認できれば四隅だけを仮設定する場合があります。強い透視変形には対応しません。すべて失敗した場合は既定値から手動で調整します。

## 3. 位置検出パターンの役割を確認・指定する

新規画像の取り込み時、ZXing-C++由来の格子が3つのFinder、白い区切り、タイミングパターンなどの厳しい照合条件を満たす場合、Finderの中心位置と左上・右上・左下の論理役割を自動設定します。自動設定したことは取り込み履歴へ記録します。この判定は正解の保証や統計的な確率ではありません。

誤った設定はFinder欄の「解除」を押し、緑のFinderをタップして個別に解除できます。設定済みのFinderをすべて解除すると論理的な向きも未確定に戻ります。四隅と既存のセル編集は残り、解除して保存した作業を開き直しても自動設定し直しません。

自動設定されなかった場合や向きを変更する場合は、見えているFinderへ論理役割を手動指定します。アプリは指定点の近傍で中心と極性を補正します。隠れたFinderを観測できたものとして指定する必要はありません。

役割が1点だけ指定され、「サンプリング位置を自動微調整する」がONの場合、その論理隅を支点とする小さな回転候補も評価します。誤った役割指定は正しい候補を妨げるため、確信できない指定は解除して比較してください。

## 4. セルを編集する

| 入力 | 意味 | 典型的な用途 |
| --- | --- | --- |
| `0` | 論理白／0 | 白と判断できるセルを指定する |
| `1` | 論理黒／1 | 黒と判断できるセルを指定する |
| `?` | 不明 | 根拠の弱い値を消失として扱う |
| `*` | 値は`?`のまま、限定的な0/1探索を優先 | 通常の消失処理で解けないときに先に確認したいセルを最大4個指定する |

「手動指定にする／画像に戻す」で、選択セルの由来を切り替えます。同じ0/1を押しただけでは手動指定になりません。一度変更した値は手動指定として残るため、画像由来へ戻す場合は「画像に戻す」またはUndoを使います。

通常画面と拡大画面では、水色の四角が手動指定、黄色の丸が選択中を示します。「手動指定セルだけ強調」は表示だけを変え、セル値、判定件数、編集履歴を変更しません。複数セル選択、Undo、Redoにも対応します。

## 5. 詳細設定を選ぶ

| 設定 | 使用を検討する場面 | 主なリスク／限界 |
| --- | --- | --- |
| サンプリング位置を自動微調整する | 四隅は概ね正しいがセル中心に小さなずれがある | 探索量が増える。バージョンと論理向きは変えない |
| 手動指定した0/1と矛盾する候補を除外する | 手動値を確実な証拠として固定したい | 1ビットでも誤ると正しい候補を除外し得る |
| 形式情報の誤り上限 | ECCレベル／マスク候補を既知形式セルへ厳しく合わせたい | 厳しすぎるとRSを試す前に候補がなくなる |
| データ・ECCの誤り上限 | 既知セルを大きく覆す候補を制限したい | `0bit`は比較可能な全既知bitとの完全一致を要求する |
| 種類・文字数／バイト数が正しく読めた場合に後続構造を強制する | 単一セグメントでモードと文字数／バイト数が正しいと確認できる | ECI、FNC1、連結QR、複数セグメントには使用しない |

設定の詳細な意味と組合せは[修復戦略](RECOVERY_STRATEGY.ja.md)を参照してください。

## 6. 修復して結果を確認する

「修復」は現在の作業を保存してから修復を実行します。「保存」は修復を実行せず、現在の作業だけを保存します。

結果では、次の順に確認します。

1. 「修復成功」「修復未完了」「修復失敗」のどれか。
2. 検証済み候補の件数と、異なる内容の有無。
3. ECCレベル、マスク、形式情報とデータ・ECCの不一致数。
4. 探索上限や候補保持上限の警告。
5. 復号内容と、重要セルの修復理由。

「詳細結果を表示」で診断を開き、セルをタップして由来を確認します。「同じコード語を表示」は、そのセルと同じ8ビットコード語に属するセルを強調します。候補が複数ある場合は、内容と候補一致範囲を比較してください。

## 7. 保存、再開、出力

保存した作業は「作業一覧」から再開できます。「操作履歴」は現在の編集経過を表示します。QRRセッションと保存元画像はアプリ専用のバックアップ対象外領域に置かれますが、暗号化ファイルではありません。

修復画像などを明示的に出力すると、アプリ専用ストレージの外へ保存されます。出力先の共有・バックアップ設定を確認してください。詳しくは[プライバシー](../PRIVACY.ja.md)と[セキュリティ](../SECURITY.ja.md)を参照してください。

## 8. 画面スタイルとナビゲーション

メニューの「画面スタイル（次回起動時）」からクラッシック／モダンを選択して保存できます。初期設定はクラッシックです。変更は次回起動時に反映され、画面回転や言語変更では適用中のスタイルを維持します。

モダン画面では「01 修復設定」「02 セル編集」「03 修復結果」のタブで移動します。結果がある場合だけ03が有効になり、タブを移動しても未保存の編集とUndo履歴を保持します。ホームへ戻る際、未保存の変更があれば確認します。
