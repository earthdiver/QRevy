# QR Repairユーザーガイド

[English](USER_GUIDE.en.md) | 日本語

このガイドは、Android版QR Repairで損傷QRを読み込み、調整、修復、確認、保存するまでの操作を説明します。内部アルゴリズムは[修復戦略](RECOVERY_STRATEGY.ja.md)、各診断項目は[修復結果情報の読み方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

修復結果は元の内容と同一であることを保証しません。URL、認証情報、送金先など重要な内容は、別の資料や手段でも確認してください。

## 1. 入力する

| 入力方法 | 向いている状況 | 注意点 |
| --- | --- | --- |
| 画像ファイル | 既に撮影・スキャンした画像がある | EXIF方向を適用して読み込む |
| カメラ | その場で撮影する | 撮影後にクロップを確定する。一時撮影画像と可逆の連携画像は使用後に削除する |
| `0 / 1 / ? / *`行列テキスト | セル判定を別手段で用意した | 許可された文字と正しいQR寸法だけを受け付ける |

テキスト入力には、編集用の[バージョン1～40の行列テンプレート](../templates/text-matrices/README.ja.md)も利用できます。

画像には、QR全体と可能なら周囲の余白が入り、各セル中心がつぶれすぎていないものを使用します。機密QR画像を公開Issueへ添付しないでください。

透明画像は、表示・解析ともに白背景へ合成して使用します。半透明の色も白と混合した後、明るさ・コントラスト・白黒反転を適用します。

## 2. 画像と幾何を調整する

1. 必要に応じて90°、1°、0.1°単位で回転します。
2. QRの範囲へクロップを合わせます。
3. 自動推定された四隅とバージョンを確認します。
4. 黒／不明／白の閾値を確認し、灰色損傷を`?`として残す範囲を調整します。
5. 色付き損傷を不明領域として使う場合だけ「自動検出された色クラスタを不明領域（?）として扱う」をONにします。初期値はOFFです。

クロップ画面の**画像調整**では、**コントラスト**または**明るさ**のスライダーを開きます。項目メニューから数値入力、項目ごとのリセット、**画像調整をすべてリセット**を行えます。**白黒反転**は通常の操作行にあります。**完了**はスライダーを閉じる操作で、解析は開始しません。

**調整前**で、クロップ・回転位置を変えずに調整前後を比較できます。解析には常に調整値が反映され、比較中の実行ボタンは**調整後で解析**と表示されます。

「閾値を自動設定」は新規画像では初期状態でONです。ONの間は、格子が変わると全体共通の閾値一組を再計算します。どちらかのスライダーを動かすと手動設定へ切り替わり、この項目を直接OFFにした場合は現在の値を維持します。手動設定の閾値は、四隅調整や修復時の自動微調整でも変わりません。ONに戻すと再計算します。セッション再開時は保存したモードと値を復元します。サンプリングが不安定なセルも`?`になる場合がありますが、固定・仮指定の編集は上書きしません。

修復前設定の閾値スライダーには、画像調整後のどの明るさを`0`・`1`と判定するかを表示します。

QRコードの隅にある四角い模様（位置検出パターン／Finder）から白黒の反転を判別できた場合は、その結果に合わせてプレビューのセル判定と閾値の説明表示を切り替えます。「自動」を選択していて、白黒の反転をまだ判別できていない場合は、Finderの位置を指定したときに、その周辺を通常・反転の両方で調べます。

自動推定値は開始値であり、正しいQRであることの証明ではありません。四隅は外周モジュールの中心へ合わせ、選択バージョンと一辺のセル数が整合することを確認します。

新規画像の四隅とバージョンは、ZXing-C++、格子周期、2つのFinderを使う補助推定の順に試します。最後の方式はバージョン2以上が対象です。対角の2つのFinderと横・縦のタイミングパターンを十分に照合できれば、位置合わせパターンがなくても右上・左下を自動設定します。照合が不十分でも、右下の位置合わせパターンが確認できれば四隅だけを仮設定する場合があります。強い透視変形には対応しません。すべて失敗した場合は既定値から手動で調整します。Finderの役割が自動設定されなかった場合は、修復前に少なくとも1つの役割を指定してください。選択範囲を正方形に射影補正すると、補正後の四隅の位置は保持しますが、Finderの役割と格子の向きは解除します。修復前に役割を再指定してください。

## 3. 位置検出パターンの役割を確認・指定する

新規画像の取り込み時、ZXing-C++由来の格子が3つのFinder、白い区切り、タイミングパターンなどの厳しい照合条件を満たす場合、Finderの中心位置と左上・右上・左下の論理役割を自動設定します。自動設定したことは取り込み履歴へ記録します。この判定は正解の保証や統計的な確率ではありません。

誤った設定はFinder欄の「解除」を押し、緑のFinderをタップして個別に解除できます。設定済みのFinderをすべて解除すると論理的な向きも未確定に戻ります。四隅と既存のセル編集は残り、解除して保存した作業を開き直しても自動設定し直しません。

自動設定されなかった場合や向きを変更する場合は、見えているFinderへ論理役割を手動指定します。アプリは指定した位置の周辺で四角い模様を探し、中心位置と白黒が反転しているかどうかを確認します。隠れたFinderを観測できたものとして指定する必要はありません。

役割が1点だけ指定され、「サンプリング位置を自動微調整する」がONの場合、その論理隅を支点とする小さな回転候補も評価します。誤った役割指定は正しい候補を妨げるため、確信できない指定は解除して役割を確認してください。すべて解除した場合は、修復前に少なくとも1つの役割を再指定してください。

## 4. セルを編集する

| 入力 | 意味 | 典型的な用途 |
| --- | --- | --- |
| `0` | 論理白／0 | 白と判断できるセルを指定する |
| `1` | 論理黒／1 | 黒と判断できるセルを指定する |
| `?` | 不明 | 根拠の弱い値を消失として扱う |
| `*` | 値は`?`のまま、限定的な0/1探索を優先 | 通常の消失処理で解けないときに先に確認したいセルを指定する（既定上限4個、最大14個に変更可） |

選択したセルについて、由来ボタンから次のいずれかを選びます。

| 由来 | 修復時の扱い |
| --- | --- |
| **画像から判定** | 編集を解除し、現在の閾値で再判定する |
| **仮指定（訂正可）** | 編集値を入力として保持するが、修復による訂正を許可する |
| **固定（訂正不可）** | 通常は、編集した0/1と矛盾する候補を除外する |

画像由来の値を異なる0/1へ変更すると固定になり、画像と同じ値に戻しても固定の指定は解除されません。画像の0/1を変えずに固定することもできます。仮指定の0/1を別の0/1へ編集した場合は仮指定を維持し、`?`や`*`から0/1へ変更した場合は固定になります。固定・仮指定の値と状態は、閾値変更、Undo／Redo、保存後も保持されます。

セル編集（拡大）では、移動・ピンチ操作中はセル記号や補助表示を一時的に隠し、元画像とQRの外枠だけを表示します。すべての指を離すか操作をキャンセルすると表示が戻ります。

水色の実線枠は固定、破線枠は仮指定、黄色の丸は選択中を示します。「指定セルを強調」は固定と仮指定の両方を対象とし、表示だけを変えます。複数セルにも同じメニューを適用できます。`?`は画像由来または仮指定、`*`は仮指定のみで、どちらも固定にはできません。

詳細設定の「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」は初期値OFFです。ONにする操作は、通常の固定動作に対する明示的な例外です。セルの由来、入力値、実線枠は固定のままですが、修復時には仮指定と同様に訂正を許可します。OFFに戻すと再び固定値を保護します。どちらの場合も、形式情報とデータ・ECCそれぞれの誤り上限、ECC・マスク・バージョンの明示指定、固定セルと明示指定の整合性検査を維持します。

`*`の指定には、四隅の位置と役割の指定が必要です。位置検出パターン・位置合わせパターン・形式情報などの固定構造や残余ビットには指定できません。対象外のセルを選ぶと、セルの種類と座標を表示します。複数選択に対象外セルが含まれる場合は、選択全体への指定を行いません。

向きを変更すると既存の`*`の位置を再確認し、対象外になった指定だけを解除して座標を案内します。値の`?`は残り、有効な`*`は維持します。バージョン変更では、確認画面で同意した後、`*`を含むセル編集全体を解除します。

詳細設定の「優先探索のセル数上限」は4〜14個に変更できます（既定4個）。実際の指定数に応じた割当て数は、4個なら16通り、14個なら16,384通りです。指定が1個増えるごとに割当て数は2倍になり、「サンプリング位置を自動微調整する」を併用すると処理量も増えます。候補保持上限はこの設定とは独立しています。上限を下げても既存の指定は保持し、超過していれば上限を戻すか指定を減らすまで修復を開始しません。

「修復の進捗」画面には現在の格子・読み取り条件の処理と経過時間を表示します。`*` の割当て試行中は、現在の格子で処理済みの割当て数と全割当て数も表示します。「修復を中断」は格子や読み取り条件の切替えを含む修復処理全体を中断し、それまでに見つかった候補を保持します。

## 5. 詳細設定を選ぶ

「入力画像を鏡像として処理する」は初期値OFFで、作業ごとに保存されます。鏡像のQR画像でONにすると、画像表示を変えずに右上・左下のFinder役割と格子の軸を入れ替えます。手動セル値、固定／仮指定の状態、Undo/Redo履歴は同じ画像上のセルに保持されます。切り替え後にデータ・ECC領域から外れる優先探索の印は、説明を表示して解除し、セルの不明値は保持します。OFFに戻すと軸を再び入れ替えます。バージョン・ECC・マスクの明示指定は引き続き適用されます。

QRの誤り訂正にはReed–Solomon（RS）符号を使います。

| 設定 | 使用を検討する場面 | 主なリスク／限界 |
| --- | --- | --- |
| 部分bit探索・自由度の上限 | 部分ビットの列挙範囲を広げる、またはRS制約を解いた後の自由度をより多く列挙したい | RSブロックごとに12・13・14ビットから選択（既定12）。1ビット増やすと最大列挙数は2倍 |
| 固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い） | 固定の指定を保持したまま、修復で訂正を許したい | 初期値OFF。ONでも誤り上限やECC・マスクの明示指定は維持する |
| サンプリング位置を自動微調整する | 四隅は概ね正しいがセル中心に小さなずれがある | 位置合わせパターンによる補正も含み、探索量が増える。バージョンと論理向きは変えない |
| 形式情報の誤り上限 | ECCレベル／マスク候補を既知形式セルへ厳しく合わせたい | 厳しすぎるとRSを試す前に候補がなくなる |
| データ・ECCの誤り上限 | 既知セルを大きく覆す候補を制限したい | `0bit`は比較可能な全既知ビットとの完全一致を要求する |
| 種類・文字数／バイト数を読み取り、または \* の試行で仮定できる場合に、単一セグメントを仮定して後続構造を強制する。 | 単一セグメントで、ヘッダーが既知または * の試行で仮定できる | ECI、FNC1、連結QR、複数セグメントには使用しない |

以下、表の最後の設定を診断表示に合わせて「単一セグメントの仮定」と呼びます。ONの場合、「3. 今回の処理」に適用状況を表示します。`*` の試行で複数の種類・文字数／バイト数を仮定した場合は、適用できた試行があったかどうかをまとめて表示します。

設定の詳細な意味と組合せは[修復戦略](RECOVERY_STRATEGY.ja.md)を参照してください。

「部分bit探索・自由度の上限」は、候補をどこまで列挙するかを指定します。12・13・14を選ぶと、最大列挙数はそれぞれ4,096・8,192・16,384通りになります。

この上限はRSブロックごとに適用します。モードや文字数／バイト数が確定せず、複数の仮説を試す場合は、仮説ごとに各ブロックの上限を判定します。そのため、探索全体の候補数は上記の最大列挙数を超えることがあります。

上限を上げるほど処理量が増え、`*`探索と併用するとさらに増えます。作業メモリや探索量にも上限があるため、設定を上げても修復候補が増えるとは限りません。

両方の誤り上限で「初期設定」「完全一致（0bit）」「厳しめ」「緩め」「手動」「制限なし」を選べ、実効ビット数を表示します。数値編集や±操作で「手動」に切り替わります。

新規読み込み時、形式情報は両コピー合計 **6ビット**（厳しめ）が初期値です。緩めは **9ビット**で、バージョンには依存しません。データ・ECCは **V1～4では総ビット数の0.875%**、**V5～40では10%**を初期値とし、整数ビットへ切り上げます。例えばV4は7ビット、V5は108ビットです。これらは運用上の折衷であり、正しい修復の保証ではありません。

「初期設定」はこのバージョン別ルールに従います。「厳しめ」「緩め」を明示的に選んだ場合は選択を維持し、バージョン変更時にビット数を再計算します。「手動」の数値と「制限なし」は明示指定として維持します。プリセット利用中も以前の手動数値を保持します。ECCとマスクの両方を明示指定した場合も、形式情報の上限を適用します。正解候補が除外される場合は、手動で上限を増やすか制限なしにして再試行してください。

リスト復号は、通常RSの訂正範囲を超えた誤りに対して、複数の候補を求める方法です。Guruswami–Sudan（GS）法、Koetter–Vardy（KV）法、Wu法を、入力と計算規模に応じて自動的に使い分けます。この追加探索では、既知ビットの不一致数をQR全体のデータ・ECCビット数の5%（切り上げ）までに制限します。「データ・ECCの誤り上限」がそれより小さい場合は、その値を使います。上限が0の場合はリスト復号を実行しません。

探索の完了状況は、指定条件と仕様で定めた範囲について表示します。候補や説明の保持省略とは区別され、完了しても修復内容の正しさや一意性を保証するものではありません。表示の意味と未完了の理由は[修復結果情報の読み方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

## 6. 修復して結果を確認する

「修復」は現在の作業を保存してから修復を実行します。「保存」は修復を実行せず、現在の作業だけを保存します。

QR構造検証と指定した入力条件を満たすものを**検証済み候補**、さらにQRデータの最終復号に成功したものを**復号済み候補**と呼びます。QRデータには文字列だけでなく、バイナリデータも含まれます。

通常の探索で復号済み候補が得られない場合や、RS部分ビット制約に頼る候補しか得られない場合は、既存候補を保持しながらリスト復号による追加探索を自動的に行います。追加探索は3方式を合わせて修復操作1回につき累計5分までで、通常の探索にかかった時間は含めません。途中でも「修復を中断」を使えます。時間切れ・メモリ不足・中断時も、それまでの検証済み候補を保持します。

結果では、次の順に確認します。

1. 検証済み候補が見つかったか、選択中の候補は復号済みか。
2. 検証済み候補の件数と、異なる内容の有無。
3. ECCレベル、マスク、形式情報とデータ・ECCの不一致数。
4. 探索完了状況、未探索の組合せ、候補の省略の有無。
5. 復号内容と、重要セルの修復理由。

「診断情報を表示」で探索と候補の診断を確認できます。「詳細結果を表示」で拡大したQRを開き、セルをタップして由来を確認します。「同じコード語を表示」は、そのセルと同じ8ビットコード語に属するセルを強調します。形式情報のセルでは役割とビット位置を表示し、計算の説明で両コピーの修復前後と固定マスク解除後の値を確認できます。ボタンは「ECCレベルのセルを表示」「マスク番号のセルを表示」「形式情報の訂正ビットを表示」に切り替わり、両コピーの関連セルを強調します。候補が複数ある場合は、内容と候補一致範囲を比較してください。

修復結果画面の「終端後の追加セグメントを解析」は、誤り訂正候補がQRデータ構造と一致せず採用されなかった場合だけ、診断情報の下に表示されます。本文の構造から特定した4ビット終端の後に残るデータを調べます。

- 終端直後からの解析に加え、次のバイト境界までがすべて既知の0なら、その境界からも解析します。どちらも連続する既知の `0000` を4ビット単位で読み飛ばし、ECIとFNC1の指定を引き継ぎます。不明ビットを0と見なして読み飛ばすことはありません。
- 追加セグメントの開始位置が複数考えられる場合は、開始位置を選んで読み取り結果を比較できます。読み飛ばしたゼロの範囲に加え、制御指定を含む各項目のビット範囲、構文解析が停止した項目と原因の範囲を表示します。未対応ECIは構文エラーと分けて示し、規格上不正な指定値とは断定しません。位置は、本文のデータの先頭をビット位置0として数え、誤り訂正用のデータは含みません。次の終端または解析停止までに構造を読めた追加セグメントを1組と数え、後続の項目で失敗しても、そこまでの結果を残します。開始位置の組合せは最大16通り、それぞれ制御指定のみの場合も含めて終端後の解析を最大16回行い、上限に達した場合はその旨を表示します。
- 解析経過にはECIの指定値と対応文字コード、失敗した項目の宣言長と残りビット数、長さ0の本文も表示します。未対応ECIが有効な間のバイト列は、以前の文字コードを流用せずHEXで保持します。後続で対応するECIに切り替われば文字変換を再開し、組全体を文字列にできない場合も個別に読めた項目を表示します。
- 「終端後の生データを表示／閉じる」では、生ビット列とHEXを確認できます。表示開始位置は、終端直後・終端後の次のバイトの先頭・指定したビット位置から選べます。不明ビットや末尾の端数は補完しません。末尾の `EC / 11` は埋め草候補として示しますが、生データからは除去しません。

これは終端後を追加のQRセグメントと仮定した診断であり、QR全体の規格適合を証明したり、拒否された候補を有効なQRへ変えたりするものではありません。表示内容は別の資料や手段でも確認してください。

拡大した修復結果では、「マスク解除」をオンにすると、選択中の候補のQRマスクを解除した修復前後の白黒を表示します。候補が未選択の場合は表示中の失敗した試行のマスクを使い、RS訂正や本文の構造検証に失敗していても操作できます。使用するマスク番号と由来を表示し、失敗した試行の番号は未検証と明示します。候補を切り替えると表示用のマスクも更新します。固定構造と不明セルはそのままです。表示だけを切り替えるため、保存されるセル値、手動編集、固定指定は変更されません。チェックを外すと元の表示に戻ります。候補・試行のどちらからもマスク番号を取得できない場合は、理由を表示してチェックを外し、操作を無効にします。狭い画面では操作列を横にスクロールできます。

## 7. 保存、再開、出力

読み込み時に、「保存」や修復を押す前から元画像とセッションを自動保存します。保存作業は最大20件で、新しい画像やテキスト行列の読み込みも件数に含まれます。上限を超えると、最終保存日時が最も古い作業と元画像を自動削除します。起動時にも上限を適用します。個別の作業は項目の長押しで削除でき、「すべて削除」で全件削除できます。

別の画像やテキスト行列を読み込んでも、前の作業の保存待ちは保持します。同じ作業で保存を繰り返した場合は、最後に保存を要求した操作履歴と選択位置を保持します。

保存した作業は「作業一覧」（クラッシックでは「最近の作業」）から再開できます。「操作履歴」は現在の編集経過を表示します。QRRセッションと保存元画像はアプリ専用のバックアップ対象外領域に置かれますが、暗号化ファイルではありません。保存形式はQRRスキーマ25です。スキーマ23・24の作業も鏡像処理OFFとして開けます。スキーマ23では「部分bit探索・自由度の上限」を12ビットとして扱います。それ以外の版の作業は開けません。

1つの作業の操作履歴は最大40件です。メモリ量や保存容量の制限により、40件より少なくなる場合もあります。容量による整理では古い履歴から削除しますが、現在選択している履歴と最新の履歴は残します。

作業や履歴を再開すると、保存時の入力と設定から修復候補を再計算します。選択したQRが記録されている場合は、候補の表示順が変わっても同じQRを選択します。そのQRが今回の探索で見つからない場合は、候補を未選択にして、その旨を表示します。

現在開いている作業を一覧から削除した後も、画面の作業は続けられます。改めて「保存」または修復を実行すると、新しい作業として保存します。

「内容をコピー」は復号した文字列全体をOSのクリップボードへ渡します。修復画像を出力すると、アプリ専用ストレージの外へ保存されます。アプリ内での作業の保存は、アプリ専用ストレージ内に留まります。出力先の共有・バックアップ設定を確認してください。詳しくは[プライバシー](../PRIVACY.ja.md)と[セキュリティ](../SECURITY.ja.md)を参照してください。

## 8. 画面スタイルとナビゲーション

メニューの「画面スタイル（次回起動時）」からクラッシック／モダンを選択して保存できます。初期設定はクラッシックです。変更は次回起動時に反映され、画面回転や言語変更では適用中のスタイルを維持します。

モダン画面では「01 修復設定」「02 セル編集」「03 修復結果」のタブで移動します。結果がある場合だけ03が有効になり、タブを移動しても未保存の編集とUndo履歴を保持します。ホームへ戻る際、未保存の変更があれば確認します。

どちらの外観でも、画面を回転しても未保存の設定・セル編集・Undo/Redo履歴を保持します。**保存**または修復を実行するまでは、保存済み作業には反映しません。

画面内のホーム／キャンセル、Androidの戻る操作、設定ダイアログ外のタップでは、未保存の変更を破棄する前に確認します。
