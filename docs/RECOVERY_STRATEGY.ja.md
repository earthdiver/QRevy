# QRevyの修復の仕組み

[English](RECOVERY_STRATEGY.en.md) | 日本語

QRevyは、画像からの読み取り、QRの構造、誤り訂正を組み合わせて、損傷したQR Code Model 2の修復候補を探します。この文書では、それぞれの情報をどう使い、どのような不確実性が残るかを説明します。

操作方法と設定は[ユーザーガイド](USER_GUIDE.ja.md)、診断の表示名とセルごとの根拠は[修復結果の見方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

## 1. 探索に使う情報

| 用語 | 意味 |
| --- | --- |
| セル（モジュール） | QRコードを構成する正方形一つ。`0`・`1`・不明（`?`）のいずれかとして読み取る。 |
| コード語 | 8ビットのまとまり。QRの内容や誤り訂正用のデータは、コード語として並んでいる。 |
| RSブロック | リード・ソロモン（Reed–Solomon、RS）符号で、まとめて誤り訂正するコード語のグループ。 |
| 誤り／消失 | 誤りは、与えられた値が間違っていて訂正が必要な状態。消失は、場所は分かるが値が欠けている状態。通常のRSでは、`?`を含むコード語を消失として扱う。 |

**修復開始時の入力**は、画像の読み取りや読み込んだ行列に手動編集を反映した状態で、構造からの推定値や探索中の仮の値を加える前のものです。読めた`0`・`1`も間違っている可能性があります。`?`は不確かなまま保持する値です。`*`も値は`?`のままで、そのセルの両方の値を優先して試すよう指定します。

誤り訂正符号（**ECC: Error Correction Code**）のデータには、誤りを検出・訂正するための情報が含まれています。候補を絞ることはできますが、それだけで作成者が記録した内容を確定できません。そのため、RSの検査に通ることは、修復候補に必要な条件の一つです。

## 2. 画像の読み方を決める

読み取り試行では、格子の位置と読み取り条件を一組選び、セルの値を読み取ります。

1. **格子を決める。** 自動推定は、編集可能な角の位置と、格子の大きさを決めるバージョンを提示します。少なくとも一つの位置検出パターン（**Finder**）に役割の割り当てが必要です。Finderが一つだけ見える場合も修復を試せます。
2. **セルを読み取る。** 明るさ、閾値、白黒の解釈、検出した色付き領域を不明と扱う設定から`0 / 1 / ?`を決めます。不安定な読み取りは不明として残し、手動編集は画像からの読み取りに優先します。
3. **必要に応じて読み取り位置を微調整する。** 格子がおおむね合っている場合は、位置・大きさ・角を少し変えると読み取りが改善することがあります。Finderの役割が一つなら、その隅を支点とした小さな回転も試せます。選んだバージョンと論理的な向きは変えません。
4. **形式情報を読む。** QR内の2か所にある形式情報は、ECCレベルとマスクを示します。マスクは番号で区別する、データセルに適用する模様です。この組み合わせに従い、データを読み取り、RSブロックに分けます。

ECCやマスクを明示した場合は、その指定に合う形式だけを調べます。それ以外では、形式情報自体の誤り訂正で形式を確認でき、入力条件も満たす場合、その読み取り試行では形式を固定します。その後のRSや内容の復号が失敗しても、別のECC・マスクの組み合わせを調べ直しません。形式の根拠が弱い場合は、優先する順序だけを決め、最初の形式が失敗したら他の許容される形式も調べます。

すべての形式に形式情報の誤り上限を適用します。もっともらしい格子や形式が得られても、元のQRコードと一致する証明にはなりません。

## 3. 読み取り試行ごとの探索順

まず仮定の少ない方法で内容の復元を試し、必要に応じて他の方法を組み合わせます。

| 段階 | 行うこと |
| --- | --- |
| 1. 修復開始時の入力で通常RS | 構造による補完やビットへの仮の値の割り当てをせず、誤りと消失を訂正する。 |
| 2. 先行するリスト復号 | ビットへの仮の値の割り当てをせず、通常RSの訂正範囲を超えて探す。先行処理の短い時間枠で終わらない分は段階5へ回す。 |
| 3. RS部分ビット制約 | 不完全なコード語に残る既知ビットを使い、不明ビットの値を求める。両立するQRデータの規則も使って候補を絞る。 |
| 4. 部分ビット探索と通常RS | 不明ビットの組み合わせを上限内で試し、その値を入れたコード語に通常RSを適用する。 |
| 5. 追加のリスト復号 | 後回しにした処理を再開し、必要に応じてビットへの仮の値の割り当ても組み合わせる。 |

段階1で、指定条件を満たし内容の復号にも成功した候補が得られた場合は、その読み取り試行の後続段階を省略します。RSの検査に通っただけの場合や、内容を復号できない候補が残っただけの場合は省略しません。後の段階で得た候補は保持し、その後の探索も続けます。

データ・ECCの誤り上限が**0ビット**の場合、段階2・4・5は省略します。段階3では引き続き、比較対象の既知データ・ECCビットをすべて保持する解を探します。上限や適用条件によって実行しない方法もあるため、毎回すべての方法を使うとは限りません。

## 4. 各方法の役割

### 通常RSと部分ビット制約

通常RSは、不完全なコード語を消失として扱います。訂正能力が足りれば、消失だけでなく、場所が分からない誤りも訂正できます。誤りの訂正には消失より多くの訂正能力を使います。訂正能力はブロックごとに決まるため、損傷がどこに分布するかも影響します。

RS部分ビット制約は、不完全なコード語の中に残る既知ビットも使います。例えば、8個のコード語にそれぞれ1ビットの不明があると、通常RSでは8語が消失になります。ビット単位の方法なら、残る56ビットを使って、その8個の不明ビットを絞り込めます。

この方法は、既知の値が正しいと仮定します。既知ビットに誤りがあると条件が矛盾する場合も、条件に合う誤った解が残る場合もあります。そのため、QRデータの構造と入力条件も確認します。RSの条件を満たす範囲で、不明ビットを独立に選べる数を**自由度**と呼び、その組み合わせを調べる数にも上限があります。

### 不明ビットと`*`を試す

部分ビット探索では、選んだ不明ビットに`0`・`1`を割り当てて訂正を試します。不明ビットが少ないコード語を優先します。部分ビット探索の上限は、RS部分ビット制約で調べる自由度の上限にも使います。ブロックごとの上限であり、QR候補の総数の上限ではありません。

`*`を使う段階でも、まず指定セルを不明のまま試します。それで内容を復号できなければ、指定したセルの値の組み合わせを試します。他の不明ビットも通常の上限内で探索できます。

例えば、`*`が2セルなら、`00`・`01`・`10`・`11`の4通りです。これらは試した値であり、新しく読み取れた情報ではありません。既知の入力ビットにはならず、入力との一致を比較するビット数にも加えません。結果には、どの値を試したかを記録します。

### QR構造を条件として使う

QRデータには、符号化方式、文字数やバイト数、内容、および終端と空き領域の埋め方の規則があります。それらを使って不明ビットを推定したり、不可能な候補を除外したりできます。例えば、数字3桁を表す10ビットは、1,000未満の数でなければなりません。

自動補完では単一セグメントの解釈を検討し、候補として残した解釈に共通する値を補うことがあります。**セグメント**は、一つの符号化方式で続けて記録されたデータのまとまりです。この推定は仮定に基づくもので、損傷したQRにセグメントが一つしかないと証明するものではありません。**単一セグメントの仮定**が無効なら、推定による補完をしない探索も残します。

この設定を有効にすると、単一セグメントの解釈と、それに必要な終端の構造を必須条件にします。宣言された個数より後の矛盾する読み取り値を置き換える場合があり、条件が適用できなくなっても黙って解除することはありません。対象となるデータと設定方法は[ユーザーガイド](USER_GUIDE.ja.md#単一セグメントの仮定)を参照してください。

### リスト復号：GS・KV・Wu

リスト復号は、通常RSが一つの答えを求める範囲を超えて、RSの条件に合う複数の答えを探す方法です。QRevyは、使える情報、処理量の見積もり、メモリに応じて方法を選びます。三つの方式を、順番に強いものへ切り替える仕組みではありません。

| 方法 | アプリでの役割 |
| --- | --- |
| **[Guruswami–Sudan（GS）法](https://ieeexplore.ieee.org/document/782097/)** | 値がそろったコード語と消失の位置を使い、探索範囲を広げる。同じ誤り数の範囲を探す二つの方法の一つ。 |
| **[Wu法](https://arxiv.org/abs/cs/0703105)** | GSと同じ誤り数の範囲を探す。処理量の見積もりと使えるメモリに応じて、どちらか一方を選ぶ。 |
| **[Koetter–Vardy（KV）法](https://www.site.uottawa.ca/~zhcheng/RS_soft_decision.pdf)** | 不明ビットの組み合わせを試す前に、部分的なコード語の既知ビットを使う。両立する値に同じ重みを与え、曖昧すぎるコード語の重みは0とする。 |

GSとWuは入力に直接使う場合と、不明ビットに仮の値を入れてから使う場合があります。不明ビットが残るコード語は消失として扱います。通常RSからの追加探索上限は、これらの追加の誤り数の範囲を制御し、KVのスコア条件は変えません。

KVは、部分的なコード語の情報が役立ち、処理量が上限に収まる場合に検討します。このアプリの重みはビットとの両立から決まり、画像の明るさ、画像の信頼度、正解の確率ではありません。新しい内容を復号できなければ、上限内で値を割り当てる探索も続けられます。

どの方法でも、それぞれの数学的な条件に加え、他の候補と同じQR・入力の検証が必要です。訂正半径、一致スコアなどの表示項目は[診断に表示される方式](RECOVERY_RESULT_FIELDS.ja.md#診断に表示される方式)を参照してください。

## 5. すべての方法で守る条件

| 条件 | 探索への影響 |
| --- | --- |
| 選んだバージョンと論理的な向き | 読み取り位置の微調整でも、別のバージョンや向きには変えない。 |
| 明示したECCレベルやマスク | 候補は指定値を満たす必要がある。 |
| 固定した`0 / 1`セル | 固定値の訂正を許容する設定を有効にした場合を除き、矛盾する候補を除外する。 |
| 仮指定と画像の読み取り値 | 適用される誤り上限の範囲で訂正できる。開始時の値は比較用に保持する。 |
| 誤り上限 | 比較対象の既知入力ビットとの不一致が上限を超えた候補を除外する。不明値や探索中の仮の値は、既知の根拠として数えない。 |
| 有効な単一セグメントの仮定 | 候補は指定した符号化方式・文字数／バイト数の解釈と、それに必要な終端の構造を保つ必要がある。 |

固定値の訂正を許容しても、元の入力値と固定の指定は保持します。ECC・マスクの明示指定と、それらの指定と固定した形式情報セルの整合性チェックは**解除しません**。誤り上限を増やすだけでも、固定セルの保護は解除されません。

例えば、保護されている固定の`0`を`1`に変える候補は、違いが1ビットだけで、誤り上限に余裕があっても除外されます。そのセルが仮指定なら変更を許容できる場合がありますが、他の検証もすべて通る必要があります。

入力との一致は、手動編集を含む修復開始時の入力と比較します。構造から推定した値や探索中に割り当てた値は、結果の正しさを別に確かめた情報にはなりません。形式情報の比較から除外するセルの詳細は[修復結果の見方](RECOVERY_RESULT_FIELDS.ja.md#入力との一致とqr設定)を参照してください。

## 6. 候補を検証し、保持して説明する

候補は、RSの検査、QRデータの構造、指定した設定、保護されたセル、誤り上限を満たす必要があります。これらを通過しても、元の内容との一致を保証しません。

候補は、内容の復号の成否、入力との一致、訂正の根拠から順序を付けます。確認しやすい順に並べるためのもので、正解の確率ではありません。異なる読み取り試行や方法で同じQRが得られた場合は、一つの候補にまとめ、別の説明は個別に保持できます。

結果の判定とセルごとの根拠は[修復結果の見方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

## 7. 完了と停止の意味

探索は有限です。ビットの組み合わせ、候補の組み合わせ、作業メモリ、候補の保持数に上限があります。探索完了は、定めた探索方針を実行し終えた意味であり、数学的に考えられるすべてのQRを調べた意味ではありません。

リスト復号の時間枠は、**修復1回につき共通で累計10分**です。通常の探索時間は含みません。また、既知のデータ・ECCビットとの不一致は、データ・ECC総ビット数の5%（切り上げ）と指定した誤り上限の小さい方に制限します。探索設定を増やしても、これらの上限は超えられません。

修復の中断、時間枠の使い切り、作業メモリ不足でも、すでに得た検証済み候補は保持し、未完了の探索を表示します。候補の保持上限は別の制限で、見つかっても一覧に残らない候補があります。この区別は[修復結果の見方](RECOVERY_RESULT_FIELDS.ja.md#探索の完了と候補の省略)を参照してください。

強いぼけ、反射、セル中心の欠損、格子設定の誤りなどで修復できない場合があります。候補がないことは実行した探索で見つからなかったという意味で、一つだけあることも一意性の証明にはなりません。重要な内容は別の手段でも確認してください。
