# QR Repairの修復戦略

[English](RECOVERY_STRATEGY.en.md) | 日本語

この文書は、QR Repairが損傷画像からQR Code Model 2の修復候補を作り、検証し、ユーザーへ根拠を示すまでの現行戦略を説明します。実装の概念的な説明であり、QR規格そのものの代替資料ではありません。

## まず全体像をつかむ

初めて読む場合は、この節、§1の三値例、§2のパイプライン一覧とケース別例、§7の限界を先に読むと、実装詳細を追わずに基本的な使い方と判定基準を把握できます。形式情報、Reed–Solomon（RS）、候補順位を確認したい場合は§3～§5へ進んでください。画面に表示される項目とセル別の根拠は、[修復結果情報の読み方](RECOVERY_RESULT_FIELDS.ja.md)と[復号・修復理由の読み方](REPAIR_REASONS.ja.md)に分けています。

QR Repairは、画像から1つの答えを推測して即座に確定するツールではありません。幾何、形式情報、誤り訂正、QRデータ構造という独立した根拠を段階的に組み合わせ、成立した候補と未解決の曖昧さを利用者へ返します。

| 表示・状態 | そこまでに確認できたこと | それだけでは保証しないこと |
| --- | --- | --- |
| RS整合 | 選択したバージョン・形式・既知ビットの下でRSの数式を満たした | 元のQR内容、正しい幾何、正しい形式 |
| 検証済み候補 | RSに加えて、QR構造と指定した入力条件を満たした | 現実世界で元の印刷物が意図した内容との一致、一意解 |
| 復号済み候補 | さらにQRデータの最終復号に成功した | 元の内容との一致 |
| 複数候補 | 検証を通過した異なる解が複数残った | どの候補が元の内容か |
| 候補なし | 実行した有限の探索範囲では検証済み候補を得られなかった | 正しい解が存在しないこと |
| 候補一致 | 比較対象となった復号済み候補間で、そのセルの値が一致した | 未保持・未探索の全解を含む数学的一意性 |
| 信頼度 | 画像証拠や処理由来を比較する説明用の目安 | 正解である統計的確率 |

## 1. 基本原則

本書では、アプリ全体の処理を「修復」、QRデータの解釈を「復号」、失われた値や保存済み履歴を戻すことを「復元」と呼びます。QRデータには文字列だけでなく、バイナリデータも含まれます。

通常のQRリーダーは、幾何と二値画像を十分な確度で取得できた場合に高速に復号します。QR Repairはそれが成立しない損傷例を対象とするため、各モジュールを次の三値で保持します。

- `0`: 論理白または論理0として観測
- `1`: 論理黒または論理1として観測
- `?`: 判定不能。Reed–Solomon処理では消失を含むコード語として扱う

手動の`*`は第四の論理値ではありません。対象セルは行列上では`?`のまま保持され、通常の消失復号試行が不成立の場合に、限定的な0/1割当てを優先して試す探索マーカーです。

修復結果には、画像由来、QR固定構造、ペイロード制約、RS修復、ユーザー編集という由来を保持します。信頼度は説明用の指標であり、統計的確率ではありません。

本書で固定値との一致を必須とする修復処理は、「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」がOFFの場合に適用します。ONでは固定の指定を保持したまま訂正を許可します。明示ECC・マスクとの整合性検査はONでも維持します（§3.1）。

### 三値と手動指定の例

次は説明用のデータビット断片であり、実在するQRの完全なコード語ではありません。

```text
画像からの観測:  1 0 ? 1 ? 0 ? 1
手動で3番目を0:   1 0 0 1 ? 0 ? 1
5番目を * 指定:   1 0 0 1 ? 0 ? 1   （値は ? のまま、優先探索情報だけを付加）
候補の一例:      1 0 0 1 1 0 0 1
```

| 操作 | 行列上の値 | 由来・制約への影響 |
| --- | --- | --- |
| 画像が明確な黒／白として読めた | `0`または`1` | 画像由来の既知値。ただし設定した誤り上限内では訂正され得る |
| 画像が曖昧 | `?` | 不明として保持し、消失復号や部分ビット制約の対象にする |
| 利用者が`0`または`1`を入力 | `0`または`1` | 固定または仮指定として、入力値と由来を保持する |
| 利用者が`*`を指定 | `?` | 通常経路が失敗した場合に、そのセルの0/1列挙を優先する |

例の最終行がRSに整合しても、それだけでは採用しません。形式情報、手動制約、誤り上限、QR構造を通過して初めて検証済み候補になります。さらに最終復号を行い、QRデータを解釈できるか確認します。

## 2. 処理パイプライン

### パイプライン一覧

| 段階 | 主な入力 | 処理 | 次へ渡すもの | この段階だけでは確定しないもの |
| --- | --- | --- | --- | --- |
| 1. 正規化 | 画像、EXIF、クロップ、回転 | 向きと輝度を整え、必要なら極性候補を用意 | 処理用輝度画像 | QRの向き・内容 |
| 2. 初期幾何 | ZXing-C++境界、格子周期、2つのFinder、利用者指定 | バージョンと四隅の開始値を作る | 編集可能な幾何 | 正しいバージョン・四隅 |
| 3. 役割と幾何候補 | 四隅、バージョン、設定済みFinder役割 | 基準・近傍・位置合わせ補正候補を作る | 有限個のサンプリング幾何 | 最良の幾何 |
| 4. モジュール化 | 輝度、閾値、色クラスタ | 各セルを`0 / 1 / ?`へ分類 | 由来付き三値行列 | 不明セルの値 |
| 5. 形式・構造 | バージョン、形式情報、機能モジュール | ECCレベル／マスク候補と固定構造を適用 | 形式ごとのコード語候補 | ペイロードの正しさ |
| 6. 制約とRS | 部分コード語、既知ビット、構造仮説 | 消失・誤り訂正、限定探索、二進制約を行う | RS整合する候補 | 元データとの一致 |
| 7. 最終検証 | 訂正後コード語 | 手動制約、誤り上限、QR構造、最終復号を検査 | 検証済み候補または診断 | 未探索領域を含む一意性 |
| 8. 説明 | 候補と各処理の履歴 | 候補順位、セル由来、追加確認箇所を表示 | 利用者が検討できる結果 | 正解確率 |

### 2.1 入力と正規化

画像ファイルではEXIF方向を補正し、カメラでは撮影後にクロップを確定します。ユーザーは90°、1°、0.1°単位の回転を指定できます。

透明部分は濃淡調整の前に白背景へ合成します。表示、輝度サンプリング、色による不明領域の判定、即時読み取りには同じ不透明画素を使用します。新規セッションには濃淡調整前の白背景合成済み画像を保存し、保存済みセッションに透明画像がある場合は、画像検証を通った後、解析用画像の準備時に合成します。

処理用画像は、各画素の明るさを表す輝度画像へ変換します。白黒が反転しているか不明な場合は、通常・反転の両方を試せます。確定した位置検出パターンの模様から通常・反転を判別できた場合は、その判別結果に従って読み取ります。余白補正が有効な場合は、位置検出パターンを探すための画像に、読み取り上の白（0）に相当する余白を補います。

コントラストと明るさは−100〜100の整数設定です。各RGB成分に対し、127.5を中心とする倍率 `2^(contrast/50)` と明るさの加算 `2.55 * brightness` を適用し、必要に応じて反転した後、0〜255に制限します。幾何補正は調整前画像に適用し、その後に濃淡を調整します。表示画素とサンプリング輝度は同じ変換を使用し、色による不明領域の判定には対応する元RGB値を保持します。読み取り極性は調整後の画像を基準とするため、反転した画像の取込み時に読み取りまで反転指定へ変更することはありません。QRRには元画像と調整値を分けて保存します。

### 2.2 バージョンと四隅の初期推定

新規画像の取り込み時は、まずZXing-C++によるModel 2の境界を検証し、採用した境界を外周モジュールの中心へ変換します。バージョン1～40と論理回転を調べ、ネイティブ側の復号文字列は修復結果へ流用しません。複数境界は、すべて同じQRを示す場合だけ統合します。

境界検証では、検出した四角形の内側にある画素だけから共通の輝度閾値を一つ推定し、周囲の背景と画像外の欠損部分を除外します。セル別・領域別の閾値は使いません。最外周セルの中心がすべて画像内にある場合はQR外周のはみ出しを許容し、中心が画像外にある格子候補は棄却します。

ネイティブ境界を採用できない場合は格子周期、続いて個別検出した2つのFinderによる幾何を試します。通常・反転の両方を調べますが、周期推定の結果が競合する場合は自動推定を見送り、後段へ進みません。また、ネイティブ境界が複数ある場合は2つのFinderによる経路を使いません。2点推定はバージョン2以上で、概ね相似変換として扱える画像が対象です。対角の2点と両軸のタイミングから右上・左下を判定でき、判定できない場合も右下の位置合わせパターンから役割を指定せず四隅だけを推定できる場合があります。

推定値は編集可能な開始値です。採用できる推定がなければ、バージョン1と既定の四隅を表示します。修復時は表示中の四隅と選択バージョンを確認済みの入力として扱うため、修復前に見直してください。

四隅の物理的位置と論理向きは別です。十分なネイティブ検出の根拠があれば3つのFinder役割を、対角2点を検証できれば2つの役割を自動設定します。周期推定だけでは役割を設定しません。自動設定は新規取り込み時だけ実行し、履歴に記録します。全役割を解除すると、四隅とセル編集を残して論理向きが未確定に戻ります。保存した役割は、再開時に再推定しません。

不一致率、曖昧な候補の扱い、通常・反転の条件、検証数値は[初期グリッド推定とFinder自動設定](ZXING_CPP_INTEGRATION.ja.md)を参照してください。これらは経験則であり、正解確率ではありません。

### 2.3 位置検出パターン役割の手動指定

自動設定の有無にかかわらず、役割は手動で指定できます。ユーザーが左上・右上・左下の役割を選び、およその中心を画像上で指定します。指定した位置の周辺で四角い模様を探し、位置検出パターンと確認できた場合は、中心位置を調整し、白黒が反転しているかどうかを判別します。検出できない場合は指定点を使用しますが、すでに位置検出パターン役割から論理格子が確定しているときは、残りの位置検出パターンについて期待位置から大きく外れた指定を受け付けません。この局所処理自体が位置検出パターンの役割を自動判断することはありません。

指定位置の周辺を調べるときは、「自動」かつ通常・反転が未確定なら両方を試します。位置検出パターンから通常・反転を判別済みの場合は、その判別結果に従います。未確定の状態で「通常」または「反転」を選んでいる場合は、選んだ方だけを試します。見つかった中心位置は、元画像上の位置として扱います。

Model 1の自動判別は現時点では実装されていません。入力対象はModel 2に限定する必要があります。

設定済みの位置検出パターン役割の数による修復時の違いは次のとおりです。画像内に見えている模様の個数ではなく、自動または手動で設定され、解除されていない論理役割を数えます。

「サンプリング位置を自動微調整する」によって指定格子の周辺を調べる処理を、本書では「近傍探索」と呼びます。

| 設定済みの役割数 | 論理向きの扱い | 近傍探索時の基準候補 | 注意点 |
| --- | --- | --- | --- |
| 0 | 表示中の四隅と既定の論理向きを使用 | 最大19 | 修復中に役割の自動探索・自動割当ては行わない |
| 1 | 指定した論理隅を支点として扱う | 最大21 | 通常19候補に時計回り・反時計回りを追加 |
| 2 | 2役割と四隅から論理向きを固定 | 最大19 | 回転2候補は追加しない |
| 3 | 3役割を明示した向きを使用 | 最大19 | 誤った役割指定は正しい候補を妨げ得る |

「サンプリング位置を自動微調整する」がONのバージョン2以上では、各基準候補に位置合わせパターン補正が最大1件加わる場合があります。詳細な上限は次節で説明します。

### 2.4 幾何候補

修復は、論理役割が割り当てられた四隅と選択バージョンを固定入力とします。まず指定幾何1通りを基準候補にします。詳細設定の「サンプリング位置を自動微調整する」を有効にした場合は、同じ論理向き・同じバージョンのまま基準候補を最大19通りへ広げます。内訳は基準1、軸方向の平行移動4、斜め方向の平行移動4、全体の拡大縮小2、一隅だけの内外移動8です。変位は0.6モジュールの1種類だけです。斜め移動は各軸を`0.6 / √2`とし、拡大縮小は四隅の平均外周変位が0.6モジュールになる倍率を用います。したがって、平行・斜め・拡大縮小の比較上の変位量は同一です。

位置検出パターン役割がちょうど1点だけ設定されている場合は、その位置検出パターン側の論理隅を固定した時計回り・反時計回りの2基準候補を追加し、基準候補を合計21通りとします。回転角は、支点から最も遠い外周隅の変位が0.6モジュールになるよう算出します。位置検出パターン役割が0点または2点以上なら回転候補は追加しません。ここまでの近傍変形どうしは組み合わせません。

「サンプリング位置を自動微調整する」がONの場合に限り、各基準候補について、バージョン 2以上で利用できる内部位置合わせパターンが十分な画像証拠を持つ場合は、補正幾何をさらに1通り追加します。予測位置との差が0.1～1.25モジュールの範囲にある位置合わせパターンを使い、その論理位置に最も近い一隅だけを動かして射影を合わせます。補正によって独立なタイミングパターン評価が大きく悪化する候補は追加しません。この処理はユーザー指定幾何を置換せず、元候補と補正候補の両方を評価します。したがって位置合わせ補正が全候補で成立した場合、候補数は「サンプリング位置を自動微調整する」がOFFで1、近傍探索時最大38、位置検出パターン役割1点を伴う近傍探索時最大42です。エンジン全体では72候補を上限とします。

どの位置合わせ候補でも、固定・仮指定の編集値を同じセル座標の入力に使います。画像の読み取り値が編集値と一致する必要はありません。詳細設定の「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」がOFFの場合、固定値と矛盾する修復候補を除外します。ONの場合は訂正を許可しますが、誤り上限や明示したQR設定には従います。

### 2.5 モジュールサンプリング

画像読み込み時に画像全体の2／3クラス輝度モデルから暫定閾値を推定し、推定できない場合は96／160を使います。この解析結果は解析画像が変わるまで再利用します。自動設定では、四隅の調整や修復時のサンプリング自動微調整を含め、格子ごとに全体共通の閾値を一組推定します。位置検出・分離・タイミング・位置合わせパターンの既知セルを黒白の根拠とし、ユーザー編集値や修復済みの値は学習用の正解にしません。3×3の領域で根拠を検証しますが、領域別の輝度補正は行いません。黒白の観測範囲が分離していれば隣接する閾値を使い、重なる場合は重複範囲を不明帯にします。安定した中央の輝度群は、複数領域の既知模様が支持する場合だけ黒または白へ含め、それ以外は不明帯へ含めます。既知模様が少ない場合や信頼できない場合は、それまでの幾何試行に依存せず、画像全体の暫定閾値を使います。

元画像全体から求めた暫定閾値を反転QRに使う場合は、明るさを反転した後も同じ範囲を区別できるように閾値を変換します。新しい暗部の閾値は「255 − 元の明部の閾値」、新しい明部の閾値は「255 − 元の暗部の閾値」です。例えば、元の閾値が40／80なら、変換後は175／215になります。格子から推定した閾値と手動で設定した閾値は、すでに白黒の反転を考慮した明るさを基準としているため、そのまま使います。

「閾値を自動設定」チェックボックスは新規画像ではONです。どちらかの閾値スライダーを変更するとOFFになり、両閾値が手動値となります。直接OFFにした場合は現在の閾値を維持します。OFFの間は四隅移動や修復時の自動微調整でも両閾値を維持し、ONに戻すと再計算して自動設定を再開します。自動／手動の選択、使用した閾値、暫定閾値はセッションに保存します。

有彩色で表された不明領域については、Lab色空間の近似色クラスタを初期推定します。クラスタ判定は色の出現量、色差の密度、黒白からの分離だけを使い、空間的なまとまり、モジュール寸法、位置検出パターン、バージョンには依存しません。基本設定のバージョンボタン直下にある「自動検出された色クラスタを不明領域（?）として扱う」は初期OFFで、ONにした場合だけ検出クラスタを分類へ適用します。灰色の領域は色クラスタではなく輝度閾値で扱います。

各セルでは、中心から各軸−0.16／0／+0.16モジュールの3×3点を、中心位置を各軸−0.1／0／+0.1モジュールずらした9位置で観測します。観測範囲を全体共通の閾値と比較する処理は、プレビューと修復で共通です。輝度を整数へ丸め、閾値の間に入る場合や微小な位置ずれで判定が変わる場合は`?`にします。手動閾値でも同じ安定性確認を行います。隣接する閾値では平均値の小数部だけを理由とする不明帯は発生しません。有効な色クラスタに属する画素が中央サンプリング領域の半分以上を占める場合も`?`にします。固定・仮指定の`0 / 1 / ?`編集は再サンプリングより優先し、由来を維持します。仮指定値は修復処理で訂正できます。固定値の訂正を許容しない場合は、その値と矛盾する候補を棄却します。

セル中心の画像座標は `0 ≤ x < 幅`、`0 ≤ y < 高さ` を満たす必要があります。補間に使える画素の範囲（`0…幅−1`、`0…高さ−1`）を超える観測点は無効とし、白埋めや端の画素の引き延ばしを行いません。ずらした9位置のそれぞれで、有効な点だけの平均を取り、9点中5点以上を必要とします。中心が画像外にある場合や、いずれかの位置で有効点が不足する場合は `?` にします。

自動推定に使う領域は、黒白それぞれ4観測以上、黒より白が明るい組合せの割合0.8以上、中央値の差が観測余裕の中央値の2倍より大きいことを条件とします。全体でも黒白それぞれ8観測以上が必要です。観測余裕は輝度0.75と中心位置ずれによる最大偏差の大きい方とし、観測範囲の端は切り捨てません。中央群の検出では各群6観測以上かつ全観測の2%以上を要求し、平滑化の尺度1／2／4で谷が隣接する低い方の峰の半分以下、隣接峰の間隔が輝度2より大きく、尺度間での中央峰の移動が6以下であることを確認します。中央群を黒または白へ含めるには、2領域以上に計8以上の支持する既知模様の観測があり、反対色の観測がないことが必要です。これらは調整可能な初期値を求める固定の経験則であり、照明や損傷による輝度の重なりには手動調整が必要になる場合があります。

### 2.6 ケース別の読み方

以下は機能の使い分けを示す合成的な例です。特定の画像や復号成功を再現する試験ベクトルではありません。

#### 例A: 位置検出パターンを1個だけ信頼できる

1. 利用者がバージョンと四隅を確認し、信頼できる位置検出パターンへ正しい論理役割を1つ指定します。
2. 「サンプリング位置を自動微調整する」を有効にすると、通常の19基準候補に支点回転2候補が加わります。
3. 各候補は同じバージョン・論理向きのままサンプリングされ、「サンプリング位置を自動微調整する」がONで位置合わせパターンの証拠があれば補正候補も別に評価されます。
4. 複数の検証済み候補が残れば、アプリは1つへ決め打ちせず候補と一致範囲を表示します。

この探索は「画像に位置検出パターンらしい形が1個ある」だけでは自動的に始まりません。役割指定は利用者の判断であり、回転候補も選択バージョンや論理向きを変更しません。

#### 例B: 灰色の損傷が複数セルを覆う

1. 黒／不明／白の閾値により、灰色部分を誤った既知値へ決め打ちせず`?`として保持します。
2. `?`を含むコード語は、通常の消失復号、限定的な部分ビット探索、RS部分ビット制約の適用対象になります。
3. RS解が一意でも、形式と既知ビットが正しいという条件付きです。QRデータ構造と最終復号を必ず続けます。
4. 解空間が曖昧なら、追加で目視確認すると自由度を1ビット減らせるセルを案内できる場合があります。

#### 例C: 手動で固定した値が誤っていた

1. 固定値との矛盾を許容しない場合、誤った手動0/1と矛盾する候補は、RSに整合していても棄却されます。
2. 形式設定との直接矛盾や、候補が要求した反対値を表示できる場合は、座標付きで診断します。
3. 根拠が弱い固定値は、値を保持する「仮指定」に変更するか、`?`または「画像から判定」に戻して再試行します。

誤り上限の変更だけでは、固定値の訂正は許可されません。固定値を訂正可能にするには、仮指定への変更または詳細設定で矛盾する修復候補の許容が必要です。

## 3. QR構造と形式情報

位置検出パターン、分離パターン、タイミングパターン、位置合わせパターン、固定暗モジュールなど、バージョンから決まる機能モジュールを構造から補います。残余ビットの表示値は選択したマスクから決まります。形式情報にはBCH訂正による候補判定を行います。バージョン7以上の型番情報は、利用者が指定したバージョンからBCHコード語を生成します。画像の型番情報をBCH復号して指定バージョンを検証する処理は行いません。固定値との矛盾を許容しない場合は、型番セルに手動入力した0/1の値と、生成した期待値との整合を確認します。

形式情報はECCレベル 4種×マスク 8種の32通りです。まず、次の場合はBCHで信頼できる候補を単独試行します。

- 2コピーとも`?`を含まず、BCH訂正後の形式情報が一致する
- 一方が完全にBCH訂正でき、他方の既知ビットが同じECCレベル／マスク候補と矛盾しない

これらに該当しない場合でも、次のいずれかでは、その形式を**暫定候補**として先に1通りだけ試します。

- 両コピーのECCレベル／マスクを表す5情報ビットが欠損なく一致し、既知のBCHパリティビットがその候補と矛盾する。この場合は、少なくとも一方のBCH領域が損傷した可能性が高い。
- 両コピーの5情報ビットがそれぞれ`?`を含むものの、重複する既知ビットが一致し、相互補完によって完全な5情報ビットを復元でき、両コピーで利用可能なBCHパリティビットがその候補と矛盾しない。

5情報ビットの一致または相互補完だけではBCH訂正済みとはみなさず、形式情報も確定しません。

BCHで信頼できる候補は、§3.2の手動入力値との整合条件を満たす場合、その幾何候補に対する確定形式として扱います。RS修復または最終QRデータ検証に失敗しても他の31形式へフォールバックしません。暫定候補は確定形式ではないため、復号済み候補が得られた場合だけ探索を終了し、成立しなければ試行済み候補を除く残り最大31通りへフォールバックします。

このBCH確定・暫定候補の単独試行は、ECCとマスクが両方とも自動の場合に適用します。どちらかを明示指定した場合は、指定で許可された形式集合を順位順に試行します。ECCのみ指定なら最大8形式、マスクのみなら最大4形式、両方指定なら1形式です。片方指定時には、BCHで信頼できる形式が含まれていても、それだけには限定しません。形式情報の誤り上限と設定に応じた手動入力値との整合条件によって、実際に試す集合はさらに絞られます。

### 3.1 手動の形式情報とECC・マスクの指定

以下の表の「固定／仮指定」はセルごとの状態です。修復時の「固定」欄は、詳細設定の「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」がOFFの場合を示します（初期値OFF）。ONでは固定の指定・入力値・実線枠を保持しつつ、仮指定と同様に訂正を許可します。ただし、編集・設定変更時の固定セルと明示ECC・マスクの整合性検査、および明示指定だけで値が決まる形式セルの比較除外は維持します。OFFに戻せば再び固定値を保護します。

**固定セルの0/1**とECC・マスクの整合性は、値・由来・設定を変更するときに確認します。2コピーの形式情報（各15ビット、BCHパリティを含む）をまとめて確認し、指定されたECC・マスクで許される候補のうち、全ての手動0/1と一致するものが1つもなければ矛盾です。画像由来と仮指定の0/1はこの判定に使いませんが、修復候補は常にECC・マスクの明示指定を満たす必要があります。

| ECC指定 | マスク指定 | 編集・設定変更時の照合先 |
| --- | --- | --- |
| 自動 | 自動 | この整合性判定は行わない |
| 指定 | 自動 | 指定ECCの8候補 |
| 自動 | 指定 | 指定マスクの4候補 |
| 指定 | 指定 | 指定された1候補（両コピーの全ビットが決まる） |

ECC・マスクの片方だけを指定した場合、単独のビットは矛盾しなくても、複数の手動ビットを同時に満たせない場合があります。その場合は、個々のビットが誤りだとは表示せず、同時に満たせないセルの組をエラー表示します。

| セル編集・ECC／マスク変更時の扱い | 固定 | 仮指定 |
| --- | --- | --- |
| 手動0/1と指定後のECC・マスクが整合する | 受け付ける | 同左 |
| 手動0/1と指定後のECC・マスクが矛盾する | 変更全体を棄却し、直前の状態・履歴を保持 | 観測値として受け付けるが、修復候補は明示指定を満たす必要がある |
| 画像由来の0/1だけが指定と矛盾する | 受け付ける | 同左 |
| 形式情報セルを `?` にする | 受け付ける。既存の手動0/1指定を消せる | 同左 |
| ECCまたはマスクを自動判定に戻す | 受け付ける | 同左 |
| 形式情報セルに `*` を指定する | 受け付けない。`*` はデータ・ECC専用 | 同左 |

表示中と同じ0/1/`?`を押すだけでは由来を変更しません（`*`から`?`への変更は優先探索指定を解除します）。画像由来のセルを異なる0/1へ変更すると固定になり、後から画像と同じ値に戻しても固定を維持します。「固定」で画像の0/1をそのまま固定できます。「仮指定（訂正可）」は現在値を保持しつつ修復での訂正を許可し、仮指定の0/1を別の0/1へ編集しても仮指定を維持します。`?`や`*`から0/1へ変更すると固定になります。詳細設定の「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」がONの場合はメニューの固定項目を「固定（修正可）」と表示します。

「画像から判定」は選択セルの編集と優先探索指定を解除し、現在の濃淡・幾何設定で再判定します。ECC・マスクの明示指定は変更しません。複数セルの由来をまとめて変更でき、Undo／Redo・保存の対象です。`?`は画像由来または仮指定、`*`は仮指定のみです。

Undo/Redoも現在のECC・マスクで再確認し、矛盾を再導入する操作は履歴を消費せず棄却します。複数セルの一括編集は一部だけ適用しません。

既存作業に矛盾がある場合、保存済みの値はそのまま読み込み、エラーを表示して自動再計算・修復を止めます。該当セルを `?` にする、またはECC・マスクを自動判定に戻す操作で修正できます。バージョンや向きの変更で矛盾が生じた場合も、保存・修復前に確認します。

### 3.2 修復時の形式情報セルの扱い

「ECC・マスク指定だけで値が決まる位置」は、**明示された設定で許される全候補に共通するビット位置**です。手動値で候補を絞った後に決まる位置は含めません。この位置の固定0/1は、前節の整合性判定で保護されるため、「形式情報の誤り上限」の一致数・不一致数・比較ビット数から除外します。

| 形式情報セルの状態 | 固定（矛盾を許容しない場合） | 仮指定 |
| --- | --- | --- |
| ECC・マスク指定だけで値が決まる位置の手動0/1 | 設定と一致する値を使用。形式情報の誤り上限の比較対象外 | 訂正可。形式情報の比較対象 |
| それ以外の位置の手動0/1 | 一致する修復候補だけを許可。形式情報の比較対象 | 変更を許可し、不一致を形式情報の誤り数に算入 |
| 画像由来の0/1 | 変更を許可し、不一致を形式情報の誤り数に算入 | 同左 |
| `?` | 固定にはできない | 候補の形式情報で補完。比較対象外 |
| `*` | 指定不可 | 同左 |

形式情報の誤り上限が0なら、比較対象の既知ビットと完全一致する候補だけを許可します。ECCとマスクを**両方**指定した場合も、指定の形式がこの上限を満たす必要があります。ただし、固定値との矛盾は前節の判定で拒否します。形式情報はいずれも「データ・ECCの誤り上限」の対象外です。

ECCとマスクが自動で、固定値との矛盾を許容しない場合、BCH候補の確定前に、形式情報・型番情報・機能モジュール・残余ビットの固定0/1との整合を確認します。矛盾する形式は確定せず、他の整合する形式も探索します。仮指定の不一致はこの棄却条件になりませんが、形式情報の誤り上限は適用します。

固定値との矛盾を許容しない場合、データ・ECCの固定値は形式確定前ではなく、訂正候補に対して確認します。形式確定後はRS修復や最終ペイロード検証に失敗しても他形式へ切り替えません。ECC・マスクの明示指定は全ての候補で守られます。

## 4. コード語、制約伝播、RS

マスクを解除して配置順に8ビットずつコード語へまとめ、バージョンとECCレベルに従って元のRSブロックへ振り分けます。1ビットでも`?`を含むコード語は部分コード語です。

RSより前に、判明しているペイロード先頭から次の安全な制約を伝播します。

- モード指示子と対応する文字数フィールドのビット幅
- オプション指定時の既知の文字数／バイト数
- 数字モードの10／7／4ビットのグループ値域
- 英数字モードの11／6ビットのグループ値域
- 終端パターン
- バイト境界の0ビット
- 交互の埋め草コード語 `0xEC / 0x11`

詳細設定の「種類・文字数／バイト数を読み取り、または \* の試行で仮定できる場合に、単一セグメントを仮定して後続構造を強制する。」を、本書では診断表示に合わせて「単一セグメントの仮定」と呼びます。

通常の構造制約は、数字・英数字・バイト・漢字の単一セグメント仮説を列挙します。既知ビットと矛盾しない仮説のうち、終端・バイト境界・埋め草の既知一致数が最大の計画群を採用し、その一致数が6ビット未満なら補いません。採用した計画群の全てで同じ値になるビットだけを補います。これは選択した単一セグメント仮説内の推論であり、複数セグメントを含むQR全体の一意性を証明するものではありません。計画列挙上限によって仮説の列挙を完了できない場合も補いません。「単一セグメントの仮定」がOFFの場合、通常の構造制約で変更を行うと、成功の有無によらず制約なしの再試行を保持します。ONの場合は条件を外した再試行を行わず、最終候補も読み取りまたは優先試行で仮定した種類・文字数と、終端・バイト境界・埋め草を守る必要があります。

「単一セグメントの仮定」は、QRの内容が数字・英数字・バイト・漢字のいずれか1つのセグメントだけで構成される場合に使用します。そのセグメント直後を終端パターン、バイト境界、埋め草として強制し、矛盾する画像由来の既知0/1も制約由来の値に置き換えます。固定セルの0/1は「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」がONの場合だけ訂正可能です。仮指定セルは訂正可能です。

信頼対象はモードと文字数／バイト数です。本文が誤読によって数字・英数字の値域外になっていても、後続領域の強制補正は行い、本文自体の訂正はRSと最終検証に任せます。

この設定は、先頭の数字・英数字・バイト・漢字モードと文字数／バイト数が既知、または明示的な `*` の割り当てで仮定できる形式候補がある場合に選択できます。通常の `?` で未確定の部分は対象外です。優先セルの割り当てごとに後続構造を評価し、仮定したヘッダーは修復根拠にも仮定として残します。自動形式でBCH確定している場合は、その形式だけで判定します。ECI・FNC1・連結QRの前置やHanziを一般診断で認識できても、この設定の対象にはなりません。ONの条件を適用できなくなった場合もONを維持して理由を表示し、条件を黙って緩和して候補を採用しません。ただし、不明領域に後続セグメントがないことは自動判定できないため、単一セグメントであることは利用者が確認してください。

通常RSでは各ブロックをGF(256)上で誤りと消失を訂正し、基本条件は`2 × errors + erasures <= ECC symbols`です。加えて、後述のRS部分ビット制約では部分コード語内の既知ビットも利用します。ただし、RS計算が数式上成功しただけでは候補を正解扱いしません。

リスト復号は、通常RSの訂正範囲を超えた誤りに対して、複数の候補を求める方法です。Guruswami–Sudan（GS）法、Koetter–Vardy（KV）法、Wu法を、入力と計算規模に応じて自動的に使い分けます。通常の探索で復号済み候補が得られない場合の追加探索に使います（4.6節）。

### 4.1 データ・ECCの誤り上限と手動入力値の扱い

誤り上限は数値を直接入力し、「−／＋」で1ビットずつ調整します。形式情報は0〜30ビット、データ・ECCは0〜選択バージョンの総コード語数×8ビットを入力できます。ECCレベルによらず総ビット数は同じです。空欄・整数以外・範囲外の値では適用できません。バージョン変更で現在の設定が最大値を超えた場合は、値を自動変更せず再指定を促します。有効な値または「制限なし」を指定するまで設定の保存・修復実行はできません。

RS修復後の各候補について、最終コード語を選択マスク付きのQRセルへ戻した値と、入力で既知のデータ・ECCセルの`0 / 1`をビット単位で比較します。`?`、形式情報、型番情報、機能モジュール、残余ビットはこの比較対象に含めません。

通常の修復では、「データ・ECCの誤り上限」を指定した場合、この不一致数が上限以下の候補だけを残します。`0bit`は比較可能な既知データ・ECCビットとの完全一致を意味し、「制限なし」では不一致数を候補の順位付けには使うものの、この値だけで棄却しません。ペイロード構造の強制によって画像由来の既知値を置き換えたビットも不一致として数えます。リスト復号による追加探索には、別途5%の上限を適用します（4.6節）。

固定値との矛盾を許容しない場合、固定セルの入力値と矛盾する候補は誤り上限の比較前に棄却します。その不一致を上限の1ビットとして消費することはありません。仮指定セルと、矛盾を許容する設定の固定セルでは、手動指定した`0 / 1`も画像由来の既知ビットと同じ扱いとなり、RSによる変更を許した上で不一致数に算入します。固定値と一致するビットは既知ビット数に含みます。

上限内の候補が1件も残らない場合は、通常のRS失敗と区別し、最良の上限超過試行について実際の不一致ビット数、既知ビット数、指定上限を診断表示します。上限0で部分ビット制約が矛盾する場合は入力済みの白黒をすべて保つRSの組合せがないと表示し、誤り数は推測しません。

セルの種類と手動入力値に対する候補除外設定の関係をまとめると、次のとおりです。形式情報については3.1・3.2節の設定との整合性判定と比較対象の除外も適用します。

| セルの種類・状態 | 固定（矛盾を許容しない場合） | 仮指定 | データ・ECCの誤り上限 |
| --- | --- | --- | --- |
| データ・ECCの手動0/1 | 値と矛盾する候補を棄却 | 変更可能。不一致を数える | 比較対象。固定で一致するビットも既知ビット数に含む |
| データ・ECCの画像由来0/1 | 変更可能。不一致を数える | 同左 | 比較対象 |
| データ・ECCの `?` / `*` | 固定にはできない | 補完・探索する | 比較対象外 |
| 形式情報の手動0/1 | 値と矛盾する候補を棄却 | 3.2節の表に従う | 対象外 |
| 形式情報の画像由来0/1 / `?` | 3.2節の表に従う | 同左 | 対象外 |
| 型番情報・機能モジュール・残余ビットの手動0/1 | QR構造・選択形式と矛盾する候補を棄却 | QR構造・選択形式による変更を許可 | 対象外 |
| 型番情報・機能モジュール・残余ビットの画像由来0/1 / `?` | QR構造・選択形式から修復・補完する | 同左 | 対象外 |

型番情報・機能モジュール・残余ビットは形式情報の誤り上限にも入りません。固定値との矛盾を許容しない場合、これらの手動入力値との矛盾は、誤り上限ではなく専用の診断（セル座標・手動値・期待値）として示します。データ・ECCの上限が正の数または制限なしでも、固定セルの手動入力値を変更する許可にはなりません。上限0では仮指定でも、比較対象の全ての既知データ・ECCビットとの一致が必要です。

### 4.2 `*`優先探索

`*`はデータ・ECCセルだけに指定できます。上限は既定4個で、詳細設定で4〜14個に変更できます。実際の指定数に応じた割当て数（`2^指定数`、最大16,384通り）を表示します。上限を下げても既存の指定は保持し、上限以内に戻すまで修復開始を止めます。セル編集画面では、四隅の位置と役割を指定してから使用します。固定構造や残余ビットを選ぶと、種類と座標を案内します。向き変更後も指定可能な位置か再確認し、対象外の`*`は`?`に戻します。バージョン変更では確認後にセル編集全体を解除します。

1. 最初は`?`と同じ消失として通常RSを試す
2. 不成立なら`*`だけに`2^指定数`通り（最大`2^14 = 16384`通り）の0/1を割り当てる
3. 各割当ての試行中にも、他の`?`に対する通常の限定探索を併用し、ペイロード検証を通る候補だけを残す
4. 複数の異なる解が残る場合は複数候補のままとし、割当てを一意に確定しない
5. すべて不成立なら、`*`の仮置きを含まない元の観測値で通常の`?`限定探索へ進む

現行実装では、手順1の通常の消失復号試行でもQRデータ制約伝播は有効です。このため、`*`がモード／文字数、終端パターン、バイト境界、埋め草、数字／英数字の値域などから一意に決まる位置にある場合、明示的な0/1割当て列挙へ進む前に制約で確定し、通常試行が成立することがあります。したがって`*`は「必ず0/1を列挙する」指定ではなく、通常の消失復号処理と安全な制約伝播で成立しなかった場合に列挙を優先する指定です。制約由来の確定は修復理由として区別して表示します。

優先探索で仮置きした0/1は、その試行内の制約であり、元入力の既知ビットには含めません。既知ビット数、不一致数、元の消失コード語数、および修復前のコード語表示は仮置き前の入力を使います。RS処理用の消失数・訂正余裕は引き続き試行時点を対象とします。明示的に列挙した座標と割当てを候補の修復履歴に保存し、通常の部分ビット探索とは区別して表示します。同じコード語内でも、優先指定していないセルに優先探索の履歴は付けません。通常経路で成立した場合は、優先探索を実施したとは記録しません。

通常の限定探索を優先割当ての試行中に併用する場合も、§4.3のRSブロックごとの上限を適用します。優先セルの最大16,384割当てと、通常列挙の選択上限4,096・8,192・16,384試行は別々の上限です。

進捗表示と中断操作は[ユーザーガイド](USER_GUIDE.ja.md#4-セルを編集する)を参照してください。

### 4.3 通常の部分ビット探索

RSの消失復号が失敗する場合、または誤りを含む訂正容量の余裕が小さい場合、部分コード語内の既知ビットが多いものを優先して、RSブロックごとに12・13・14ビットから選ぶ共通上限（既定12）で列挙します。試行数はそれぞれ最大4,096・8,192・16,384回です。同じ設定を、完全一致のRS制約経路で列挙する残り自由度の上限にも適用します。複数の未知位置の誤りに必要な容量を確保できる範囲まで部分消失コード語を確定します。

これはRSブロックごとの上限です。通常列挙の対象は、不明ビットが1〜4個のコード語だけです。不明ビット数が少ない順に選び、同数ならブロック内のコード語順を保ちます。不明ビットが5〜8個のコード語はこの経路では消失のままですが、別の二進制約経路では利用できる場合があります。

### 4.4 RS部分ビット制約

形式候補・RSブロックごとに、GF(256)のシンドロームが0となる式を、不明ビットを変数とするGF(2)の式に展開します。データ・ECC双方の既知ビットを定数とし、行基本変形によって矛盾の有無と、自由度`d = 不明ビット数 − rank`のアフィン解空間を求めます。全解で共通のビットと、独立な追加確認ビットは、解の列挙なしで算出できます。

- データ・ECCの誤り上限0では、この完全一致経路をブロック候補生成に使います。上限が正または制限なしの場合は通常RSの誤り・消失復号経路と候補を併合し、完全一致解が得られても通常RSの経路を省略しません。任意の誤りビット数上限に対する誤り位置の全探索ではありません。
- `d = 0`なら条件付きのRS解が1つ、`d`が1以上で選択した部分ビット上限（12・13・14）以下なら全`2^d`割当てをQR検証へ渡します。それ以上は一部を恣意的に抜き出さず、解空間を記号的に扱います。QR全体の組合せ探索には別途上限があります。
- `*`優先探索前の通常試行では、`*`も不明セルとして扱い、部分ビット制約からは自由度0の解のみを候補生成に使います。この段階では自由変数の列挙も通常の部分ビット探索も行いません。復号できなければ`*`へ0/1を割り当て、各割当て内で設定上限までの部分ビット探索と自由度の列挙を行います。どの割当てでも復号できなければ、仮置きを含まない元入力に戻り、`*`を含むコード語を列挙対象から除いて通常の部分ビット探索を試します。探索順序は§4.2を参照してください。
- ペイロード構造制約によって候補生成用の自由度が減ることがあります。「単一セグメントの仮定」がOFFの場合は、構造制約なしの再試行も行います。診断と追加確認の案内は、構造による強制や一時的な`*`割当てを含まない入力時点を対象とします。
- 全解共通ビットで元行列を上書きしたり、手動入力した値として扱ったりしません。完成した候補にはRS部分ビット制約由来であることを記録します。二進行列の階数を通常のシンボル訂正余裕に読み替えません。
- 既知ECCの誤りによって、制約が矛盾するだけでなく、誤った整合解が得られることもあります。一意解でもバージョン・形式・既知ビットが正しいという条件付きです。ペイロード検証、設定に応じた手動入力値との整合、最終不一致数の検査は省略しません。

例えばV1-Lで20コード語に1ビットずつ消失が分散していても、二進行列の階数が20なら一意に解けます。通常RSの7コード語の消失訂正容量と12ビットの部分ビット探索だけでは解けないケースです。一方、ECC全7バイトとデータ4ビットが消失した場合は自由度4、RS割当て16通りです。ECCが全消失なら、RSだけで不明なデータを追加で確定することはできません。

### 4.5 誤り上限プリセットの採用理由

両方の上限で「初期設定」「完全一致（0bit）」「厳しめ」「緩め」「手動」「制限なし」を選べます。選択とバージョン変更時の動作は[ユーザーガイド](USER_GUIDE.ja.md)を参照してください。プリセットは運用上の折衷であり、正しさの保証ではありません。

- **形式情報：** 厳しめと初期設定は両コピー合計6ビット、緩めは9ビットで、バージョンには依存しません。15ビットの形式情報を2コピーとも既知とした符号の最小距離は14なので、半径6以内に入る形式は高々1つです。各コピー3ビット誤りの全207,025配置を列挙し、6ビットで正しい形式だけを保持しました。9ビットでは片コピー無傷・他方8ビット誤りも保持できますが、別形式も許容する場合があります。不明セルは数えず、全形式セルが不明ならこれらの上限では絞れません。
- **データ・ECC：** 厳しめは抑制優先の評価に基づき総ビット数の0.875%、緩めは10%を整数ビットへ切り上げます。初期設定はV1～4が厳しめ、V5～40が緩めです。このバージョン境界は小さいQRを目視で手動入力する用途を想定した運用上の選択であり、精度の測定から得た境界ではありません。
- **緩めの比較：** 合成8,012条件・修復32,048回では、5%で元のQRを正確に保持した条件が2,627件、別の復号内容を含む条件が32件でした。10%ではそれぞれ3,231件・37件、制限なしでは3,874件・45件でした。この比較から正解保持と別候補抑制の折衷として10%を選びました。同じ条件に正解と別の内容が同時に残る場合があります。

条件は生成元のQRを共有しており、独立した実写画像の評価ではありません。結果は損傷分布・seed・評価の重み・有限の探索／保持枠に依存します。10%選択後の新たな未使用確認群はなく、既知ビットの変更が0の別候補は上限だけでは排除できません。再利用できる評価・列挙の手順は[評価ツール](../tools/detector-study/README.md#synthetic-dataecc-error-limit-study)に残し、詳細な実行記録は製品文書とは別のローカル調査資料として扱います。

QRRスキーマ25は各上限の選択状態と保持中の手動数値を別々に保存します。完全一致はバージョン変更後も0ビットを維持します。ECC・マスクの明示指定と固定セル保護は、それぞれ独立した規則を維持します。

### 4.6 リスト復号による追加探索

各読み取り入力について、通常RS・RS部分ビット制約・部分ビット探索・優先探索で復号済み候補が得られなかった場合、リスト復号による追加探索を行います。データ・ECCの誤り上限が0の場合は実行しません。

GS法とWu法は、不明ビットが残るコード語を消失として扱い、通常RSの訂正範囲より1コード語多い誤りを対象とします。Johnson境界の条件を満たす場合に、見積もった計算量と作業メモリから方式を選びます。GS法は消失位置を除いて補間し、候補多項式を元の全位置で評価します。Wu法は誤り位置を表す多項式を利用し、この訂正範囲では定数・一次式の計算で候補を求めます。同じ訂正範囲を両方式で重複して探索しません。

KV法は、未知ビットの割当てを列挙する前に、部分コード語内の既知ビットを利用します。不明ビットが1〜4個のコード語について、既知ビットと一致する値に補間の重み（多重度）を均等に配分します。不明ビットが多いコード語は補間から除きます。この重みは画像の信頼度や正答確率ではありません。候補を得られる条件と計算規模を見積もり、利用できる場合だけ試します。復号済み候補が得られなければ、部分ビット探索へ進みます。

部分ビット探索は4.3節と同じ条件で行い、元が不明なビットだけに0/1を割り当てます。各割当てにGS法またはWu法を適用します。元入力の消失数が多すぎても、KV法で部分コード語の情報を利用したり、割当てで消失数を減らしたりすることで復号できる場合があります。各候補のRS整合性と、各方式の訂正範囲または一致スコアの条件を確認します。通常RSの結果から対象範囲内に別候補がないと証明できる場合などは、その範囲の復号計算を省略します。

既知ビットの不一致数は、**QR全体のデータ・ECCビット数の5%（切り上げ）**までに制限します。「データ・ECCの誤り上限」がそれより小さい場合は、その値を使います。比較対象は構造補完や仮置き前の元入力で、部分コード語内の既知ビットも含みます。不明ビットの補完は不一致に数えません。ブロックを組み合わせるときも不一致数を合計し、上限を超える候補はQR検証前に除外します。

各試行の候補を通常RSの候補と統合し、候補が増えるたびにQR構造・ペイロードを検証します。通常RSで成功済みのブロックも、別候補を探索します。固定セルや優先割当てなどの入力条件を適用し、複数の有効候補は保持します。形式・構造の各試行では、候補の組合せと探索ノードをそれぞれ最大65,536とします。

追加探索は3方式を合わせて、修復操作1回につき**累計5分**までで、通常の探索にかかった時間は含めません。作業メモリの上限は通常の探索と共有します。計算中も中断でき、時間切れ・メモリ不足・中断時は、それまでの検証済み候補を保持して、未完了の理由を表示します。

アルゴリズムの参考: [Guruswami–Sudanの誤り・消失対応](https://www.site.uottawa.ca/~zhcheng/list_dec.pdf)、[Nielsen–Zehの補間と根探索](https://arxiv.org/abs/1404.3022)、[Koetter–Ma–Vardyの補間法](https://arxiv.org/abs/1005.5734)、[Wuの誤り位置多項式によるリスト復号](https://arxiv.org/abs/cs/0703105)。

## 5. 候補の検証と順位

固定値との矛盾を許容しない場合の固定0/1違反、コード語外の固定構造との矛盾、指定された誤り上限の超過、QRデータ構造の不正を理由に候補を棄却します。RS整合だけでは候補を保持しません。検証済み候補に対して最終復号を行い、QRデータを解釈できるか確認します。

保持した候補の比較器は、次の順に比較します。同順位なら発見順を保ち、幾何間では最後に画像の幾何スコアを使います。

1. 最終復号の成立を優先
2. 形式情報の不一致数が少ない
3. 形式情報の一致数が多い
4. 元入力の既知データ・ECCビットとの不一致数が少ない
5. 比較できた既知ビット数が多い
6. 最小RS余裕が大きい
7. 部分ビット探索数が少ない
8. 訂正対象シンボル数が少ない
9. 修復時の消失コード語数が少ない

構造制約の確定ビット数は診断情報であり、この比較器の順位条件には含めません。RS部分ビット制約経路の内部余裕値は0ですが、画面ではシンボル余裕の算定対象外と表示します。

幾何・極性が異なる試行でも、同じバージョン・ECC・マスク・訂正後コード語列は1結果へ集約します。別経路の診断と由来は保持上限内で残し、省略した場合は明示します。主表示は最良経路の由来を使用し、経路数を修復結果数として数えません。

同じブロック解を得た通常消失復号・列挙経路も、後から見つかったものを含め、異なる経路情報を保持します。通常RSの代表経路は、RS余裕が大きい、探索ビットが少ない、対象シンボルが少ない、ペナルティが小さい順で選び、完全同順位は発見順です。同値の二進制約経路があっても通常RSの経路を代表にします。組合せ探索の順序には、これとは独立して全保持経路の最小ペナルティを使います。探索順位の改善によって代表経路自身の診断値を書き換えることはありません。

最終QRデータ検証の成否を最優先し、未成立候補どうしでは形式情報の不一致数をRS成功より強い順位条件として扱います。したがって、形式情報と大きく矛盾するRS整合解が、形式情報に整合して消失容量不足がわずかな失敗試行より診断上よい候補とみなされることはありません。既知セルを大量に覆す候補、許容されていない固定0/1との矛盾を含む候補、構造上不正な候補は棄却または低順位になります。

RSブロックを組み合わせる途中では、入力が次のモード指示子の途中で終了する場合があります。途中検証では未完部分を理由に棄却せず、完成したデータ列に対して終端・バイト境界・埋め草を含む最終検証を行います。途中検証の通過は復号成功を意味しません。

複数RSブロックに候補がある場合、組合せを評価順に初期4,096件まで調べ、復号済み候補がまだ得られなければ8,192、16,384、32,768、65,536件へ探索窓を倍増します。QRビットストリームとして成立してもZXingでQRデータを解釈できない候補だけでは探索を終了しません。上限まで復号済み候補が得られなければ、組合せ探索上限として診断します。

順位順のprefix探索は、直積の訪問済み集合を保持せず、兄弟ノードを必要時に生成します。さらに形式・構造制約の試行ごとに、QR検証で棄却したprefixも含む展開ノード数を65536までとします。完成した組合せがほぼ成立しない場合にも処理量と探索待ちのメモリを制限します。固定上限への到達は探索仕様上の完了であり、その範囲外に正しいペイロードが存在しない証明ではありません。

検証済み候補が得られなかった場合は、形式ごとの参考診断とセル確認の案内に使う代表的な失敗を1件保持します。形式情報の不一致、消失容量不足ビット数、既知ビットとの整合、消失数などで比較します。これとは別に、形式・幾何・読み取り条件を通じた入力条件の矛盾、候補の不採用理由、未探索範囲を集計します。最終結果の説明には集計結果を使い、代表的な失敗1件を探索全体の理由として扱いません。元行列を推測値で上書きしません。

QR組合せ探索の診断では、成功後の探索区間終了・組合せ数上限・処理ノード数上限を区別します。

探索完了は、指定条件と仕様で定めた範囲の処理を終えたことを表します。通常RSでの成功による探索の省略、選択した12・13・14ビット（最大4,096・8,192・16,384回）の部分ビット探索、列挙上限を超える解空間の解析、組合せ数・処理ノード数・格子候補数の上限到達は、仕様内の終了です。利用者の中断、リスト復号の時間切れ、作業メモリ不足、内部エラーで必要な処理を実行できなかった場合は未探索ありとし、実行記録が足りなければ判定不能とします。候補や説明の保持省略は別に報告します。表示文言と読み方は[修復結果情報の読み方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

FNC1第2位置の8ビットのアプリケーション識別子は本文と分離して保持します。ZXing 3.5.4へ渡す復号専用列からだけ識別子を除き、元のコード語、RS整合性、構造検証、不一致数は元の列に基づきます。連結QRが先行する場合も同様です。

漢字・Hanziモードは13ビット値から文字コードを復元し、QRで許可されたバイト範囲とShift_JIS／GB2312の割当てを検査します。不正列を置換文字へ変換しただけでは成功としません。前方検証も、文字の全13ビットが揃った時点で同じ検査を行います。バイトモードの任意バイナリにこの文字制約は適用しません。

連結QRは先頭に1回だけ許可し、総数2～16と0始まりの番号が総数未満であることを検査します。番号・総数・8ビットのパリティは復号結果に保持します。このアプリは各QRを修復しますが、複数QRの連結と全体のパリティ照合は行いません。

## 6. 結果の説明

各修復処理と、幾何・極性を通じた探索全体で、順位上位256種類までのQR候補を保持します。後から高順位の結果が見つかれば先行候補を置き換え、下位候補の詳細を解放しても探索範囲の計算は続けます。代表候補の入力行列と共有説明データも保持予算へ算入します。別経路の詳細にも上限を設け、詳細の省略と探索未完了を区別して表示します。セル別説明は参照時に生成します。

Androidアプリは利用可能なJavaヒープを基に、結果保持・実行中の試行・ソルバの予算を分け、表示とランタイム用の余裕を残します。これらは保守的な計算上の見積もりであり、Androidプロセス全体の実測値や厳密な上限ではありません。ブロック候補リストの確保前と組合せ探索の展開前に作業メモリを確認し、その上限で止まった場合は未探索の組合せがあることを表示します。失敗試行の行列は最良の参照のみ保持しますが、簡潔な診断と試行した幾何の情報は探索全体を対象とします。

候補一致と確認セルの案内は、選択中と同じ入力行列に由来する復号済み候補を重複なしで比較します。比較用に候補ごとのQR行列を生成するため、メモリ量と計算量を抑える上限として上位16件までを使います。選択中の復号済み候補が範囲外なら末尾を置き換えます。比較対象数と、この入力に由来して保持している復号済み候補の総数を明記し、一部の一致を全候補の一致とは扱いません。QR構造検証には通っても最終復号に成功していない候補は、選択・出力できてもこの集計には含めません。

QRRスキーマ25の履歴には、選択QRのバージョン・ECC・マスク・訂正後コード語列と、実際のサンプリング極性を保存します。再計算後は候補の一覧番号ではなくQRの同一性で選択を復元し、一致する候補がなければ未選択とします。実際の極性は、利用者の自動／通常／反転という探索設定とは別に記録します。履歴件数と容量制限の利用者向け説明は[ユーザーガイド](USER_GUIDE.ja.md#7-保存再開出力)を参照してください。

固定値との矛盾を許容しない場合、データ・ECCの手動入力値と矛盾する候補を棄却するとともに競合座標と入力値・候補要求値を記録します。一般的なペイロード失敗より具体的な診断を同条件で優先します。一時的な優先割当ては、利用者が手動入力した0/1の値とは扱いません。

結果行列ではセルごとに修復理由を保持します。セルをタップすると、値、由来、適用された構造／制約／RS処理、説明用の信頼度を表示します。「同じコード語を表示」を押した場合だけ、そのコード語を構成する8セルを強調します。

修復後に値が一意に定まったセルは0または1で表示します。QR規格上デコード判定に不要な残余ビットなどと、本当に未確定の`?`は区別します。

検証済み候補がなくても、矛盾のない曖昧な完全一致RS解空間があれば、条件付きの追加確認セルを表示できます。対象は不明なデータ・ECCセルのみで、ファインダ等の機能モジュールや残余ビットは含めません。アフィン空間の非定数ビットはどれも解空間を二分するため、独立なビットを選ぶことで後続の確認も有効になります。同条件なら画像信頼度の高いセルを優先しますが、これは読みやすさの目安にすぎません。画面にはRS自由度が1ビット減ることと、形式・既知ビットの完全一致を仮定することを明示します。検証済みQR候補数や、誤りを許す全解に対する保証ではありません。矛盾する解空間や自由度0の場合には、この推奨セルは表示しません。

## 7. 停止条件と限界

- キャンセルまたは新しい設定による設定世代の変更を検出した処理は、古い結果をUIへ反映しません。
- 幾何・形式・ブロック・二進消去・ペイロード仮説・割当て／前方探索の区切りでも、プラットフォーム非依存の中断確認によって計算を停止します。Android側は設定世代とスレッドの割込みを確認します。中断は幾何候補の例外処理で握りつぶさず、QR修復失敗とも表示しません。協調的な停止であり、個々の演算を即時に中断する仕組みではありません。
- 前処理設定の保存で待機中・実行中の修復結果を無効化し、以前の結果選択を消去します。修復と履歴の再計算は、キューへ投入する前に設定のスナップショットを取得し、その設定でサンプリング・復号します。
- 幾何、形式、ビット列挙には上限を設け、探索空間を有限に保ちます。
- Model 1、Micro QR、rMQRは非対応です。
- 強い反射、極端なぼけ、セル中心の欠落、誤ったバージョン／四隅固定は、訂正能力内でも修復を妨げます。
- RS整合する別解が理論上存在し得るため、重要情報は必ず外部で確認してください。

## 8. 実装境界

位置検出パターン検出、幾何、三値行列、GF(256) RS、部分ビット探索、QRデータ制約の主要処理は`shared/src/commonMain`にあります。ZXingに依存するバージョン・形式情報・ブロックのインターリーブと最終復号は現在`androidApp`にあります。この境界により、共有コアをAndroid APIやJVM専用APIから独立させています。
