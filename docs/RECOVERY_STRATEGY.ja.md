# QRevyの修復戦略

[English](RECOVERY_STRATEGY.en.md) | 日本語

QRevyは、損傷したQR Code Model 2について、画像の読み取り、QRの構造、誤り訂正を組み合わせて修復候補を探します。この文書は、候補がどのように生まれ、どの条件で除外されるかを説明します。

処理の流れは次のとおりです。

`格子を決める → セルを読む → 形式を選ぶ → コード語を修復する → ブロックを組み合わせる → QR全体を検証する`

操作方法は[ユーザーガイド](USER_GUIDE.ja.md)、診断項目とセルの説明は[修復結果の見方](RECOVERY_RESULT_FIELDS.ja.md)を参照してください。

## 1. 読み取り情報と計算上の仮定

QRコードを構成する正方形一つをセル（モジュール）と呼びます。セルの値は`0 / 1 / ?`で保持します。`?`は不明を表します。画像から読み取れた値にも誤りの可能性があります。

画像または読み込んだ行列に手動編集を反映した状態を、構造から補った値や探索中の仮の値を加える前の入力として保持し、結果との比較に使います。この状態を「修復開始時の入力」と呼びます。

`*`は、指定した不明セルの`0 / 1`の組み合わせを優先して試す指定です。セルの値は`?`のままで、計算中に試した値は入力との一致・不一致の比較から除外します。

### 値の由来、固定セル、比較対象

各セルでは、入力値、計算途中の補完・訂正、最終値を区別します。

例えば、構造から`0`を補い、その後の誤り訂正で`1`になった場合は、「構造から`0`を補完」「誤り訂正で`1`に変更」という順序を記録します。

固定したセルの`0 / 1`と異なる値を持つ候補は、固定値の訂正を許容する設定が無効なら除外します。仮指定のセルや画像から読み取ったセルの値は、誤り上限の範囲内で訂正できます。固定値の訂正を許容した場合も、入力には元の値と固定の指定を記録しておきます。

誤り訂正符号（**ECC：Error Correction Code**）は、データの誤りを検出・訂正するための情報です。データとECCのビットについて、修復開始時の入力値と候補の値を比較します。

| 値 | 比較対象 | 理由 |
| --- | --- | --- |
| 修復開始時の既知データ・ECCビット | 含める | 読み取りや手動編集で得た入力値であるため |
| 開始時の`?`や`*` | 除外する | 比較する入力値が分からないため |
| 構造から補った値 | 除外する | 計算で推定した値であり、修復開始時の入力値ではないため |
| 探索中に試した値 | 除外する | 組み合わせを試すための仮の値であるため |

開始時に既知だった値を計算途中で変更した場合は、元の値を比較対象に含めます。例えば、開始時の`0`を構造に合わせて`1`へ変更した場合、最終結果が`1`なら不一致は1ビットです。開始時が`?`なら、途中で`0`を補って最終結果が`1`になっても、そのセルは比較対象から除外します。

誤り上限を増やすだけでは、固定値の訂正は許可されません。固定値も訂正の対象にするには、固定値の訂正を許容する設定を有効にします。

## 2. 格子とセルの読み取り

画像の取り込み時には、格子の大きさを決めるバージョンと、QRコードの四隅が画像上のどこにあるかを推定します。修復中は、その格子を基準に読み取り位置を微調整します。選択したバージョンと、QR上の左上・右上・左下の対応関係（論理的な向き）は変えません。

修復には少なくとも一つの位置検出パターン（Finder）について、左上・右上・左下のどれに当たるかを割り当てる必要があります。Finderが一つしか見えない場合も修復を試せます。

セルの中心付近で読み取り位置を少しずつ変え、毎回同じ黒・白の判定になる場合は`0 / 1`にします。判定が変わる場合や、黒・白を判別できない場合は、不明を表す`?`にします。

手動で編集したセルには、画像から読み取った値の代わりに、指定された`0 / 1 / ?`を使います。

### 初期格子と微調整の作り方

初期推定では、QRコード検出ライブラリのZXing-C++で、画像中のQRコードの外周を検出します。検出した外周から格子を作り、Finderなどが期待される位置と模様で読み取れるかを検証します。

その格子を採用できない場合は、セルの繰り返し間隔から格子を推定し、それも採用できなければ2個のFinderを使った推定を検討します。異なるQRコードの外周が見つかる場合や、通常の白黒で読むか反転して読むかによって推定結果が異なる場合などは、推定結果を採用しないことがあります。検出ライブラリが読み取った文字列は修復結果には使いません。

四隅から画像上のセル位置を求める際には、平面を斜めから見たときの変形を表す射影変換を使います。曲面に印刷されたQRコードのゆがみを正確に表すことはできません。

微調整の基本候補は次のとおりです。

| 変形 | 候補数 |
| --- | ---: |
| 指定した格子 | 1 |
| 軸方向・斜め方向への平行移動 | 8 |
| 拡大・縮小 | 2 |
| 一隅だけの内側・外側への移動 | 8 |
| 合計 | 19 |

位置を動かす量の基準はセル幅の0.6倍です。Finderの役割を一つだけ割り当てている場合は、そのFinderに対応する隅を支点として、時計回りと反時計回りに少し回転させた格子も試します。この2通りを加えると、格子の候補は最大21通りになります。それぞれの移動・拡大縮小・回転は、指定した格子に一種類ずつ適用して試します。

バージョン2以上では、格子の位置を合わせるための小さな模様である位置合わせパターンを使い、各格子候補に補正した格子を最大一つ追加できます。予測位置とのずれがセル幅の0.1～1.25倍なら、そのパターンに最も近い格子の隅を動かします。セルの間隔を示す黒白交互の模様であるタイミングパターンとの一致が大きく悪化する補正は除き、元の格子候補も残します。

補正した格子を含む候補数は最大38、Finderの役割を一つだけ割り当てている場合は最大42です。微調整を無効にすると指定格子1通りを使います。

### 明るさの測定と不明判定

各セルでは、中心から横・縦それぞれに−0.16、0、＋0.16セル離れた3×3点で明るさを測り、その平均を求めます。この3×3点全体を横・縦それぞれに−0.1、0、＋0.1セルずらし、9か所の平均値の最小値と最大値を調べます。

黒と判定する明るさの上限、白と判定する明るさの下限を、それぞれ閾値と呼びます。測定した最小値と最大値の両方が黒、または両方が白と判定される場合にだけセルの値を決めます。二つの閾値の間に入る場合や、小さな位置ずれで判定が変わる場合は`?`です。各測定位置で9点中5点未満しか画像内で測れない場合も不明にします。

自動閾値は、Finder、その周囲の白い分離パターン、タイミングパターン、位置合わせパターンの黒白が決まっているセルを使って推定します。複数の領域で測定値が黒白の模様に合うかを確認し、格子全体に共通の二つの閾値を求めます。十分な測定値が得られない場合や、測定値が模様と合わない場合は、画像全体から求めた暫定値を使います。

閾値を手動で設定した場合は、格子を微調整するときも同じ閾値で読み取ります。

色付き領域を不明として扱う設定を有効にすると、自動検出した色のグループに該当するセルを`?`にします。色のグループは、画像内の似た色をまとめて求めます。

## 3. 形式情報からRSブロックを作る

QRコードには、ECCレベルとマスク番号を記録した「形式情報」があります。マスクは、データセルを規則に従って白黒反転するための模様です。この文書では、ECCレベルとマスク番号の組み合わせを「形式」と呼びます。

形式を選んだ後、Finderや形式情報などのデータ以外のセルを除き、データをQRの配置順に読みます。マスクによる白黒反転を元に戻し、8ビットずつのコード語にまとめます。さらに、交互に配置されたコード語を、まとめて誤り訂正するグループであるRSブロックに分けます。RSはリード・ソロモン（Reed–Solomon）符号の略です。

ECCレベルやマスク番号を明示した場合は、その指定に合う形式だけを試します。固定した形式情報セルがある場合は、その値が指定したECC・マスクと矛盾していないかも検査します。この検査は、固定値の訂正を許容する設定が有効でも行います。

一組の格子と読み取り条件でセルを読み、修復を試す処理を「読み取り試行」と呼びます。形式情報の誤り訂正で形式を確認でき、入力条件も満たす場合は、その読み取り試行では確認した形式だけを使います。後の修復に失敗しても、別の形式を試すことはありません。

### 形式情報と入力値の比較

形式情報についても、修復開始時の入力値と候補の値を比較します。ただし、明示したECC・マスクだけで値が決まる固定セルは、比較から除外します。設定から決まる値を、その設定が画像と一致しているかの判断に使わないためです。仮指定の形式情報セルは比較に含めます。

例えば、ECCレベルを「M」、マスク番号を「0」に指定すると、形式情報の各セルが`0 / 1`のどちらになるかが決まります。そのうち、設定から`1`と決まるセルを考えます。

| そのセルの入力 | 比較での扱い |
| --- | --- |
| `1`に固定 | 比較から除外する。設定と同じ値であることを、一致したビットとしては数えない |
| `1`を仮指定 | 比較に含め、候補の値との一致を1ビットと数える |
| 画像から`1`と読み取った | 比較に含め、候補の値との一致を1ビットと数える |

固定した値と設定が矛盾していないかは、前述の整合性検査で確認します。

### 形式の確定と、優先順位だけを付ける場合

形式は4種類のECCレベルと8種類のマスクの組み合わせで、最大32通りあります。QR内の2か所に、同じ内容の15ビットの形式情報が記録されています。

形式情報にはBose–Chaudhuri–Hocquenghem（BCH）符号による誤り訂正を使います。QRevyが形式を確認する主な条件は次のとおりです。

- 両方の形式情報が全ビット読める場合：それぞれ3ビット以内の訂正で同じ形式になる。
- 一方だけ全ビット読める場合：その側が訂正でき、他方の既知ビットが訂正後の形式とすべて一致する。

さらに、形式情報の入力値との不一致が誤り上限以内か、訂正を許容していない固定セルと矛盾していないかを確認します。これらの条件を満たす場合に、その読み取り試行で使う形式を確定します。

形式を固定する条件を満たさなくても、ECC・マスクを表すビットがそろうなどの理由で、先に試す形式を選べる場合があります。その形式で内容を復号できなければ、設定と誤り上限に合う他の形式も試します。

コード語抽出では不明ビットの位置も保持します。インターリーブ解除は、QR上で交互に並べられたコード語を、誤り訂正する元のブロックへ戻す操作です。各ブロックのデータ語数とECC語数は、バージョンとECCレベルで決まります。

## 4. 読み取り試行ごとの探索順

| 順序 | 処理 |
| --- | --- |
| 1 | 補完や仮の値を加える前の入力で通常RS |
| 2 | 短い時間枠で先行するリスト復号 |
| 3 | RS部分ビット制約とQR構造による絞り込み |
| 4 | 部分ビット探索と通常RS |
| 5 | 既知bit誤りの追加探索。有効で、それまでに内容を復号できた候補がない場合に実行 |
| 6 | 追加のリスト復号。必要に応じて仮の値の探索も併用 |

段階1でQR構造・入力条件の検証と内容の復号に成功した場合は、その読み取り試行を終えます。それ以外は後続段階へ進みます。段階2以降で候補が得られた場合は、その候補を残して探索を続けます。ただし、段階5は「既知bit誤りの追加探索」がONで、段階4までに内容を復号できた候補がない場合だけ実行します。段階5で候補が得られても、段階6は試みます。

データ・ECCの誤り上限が0ビットなら段階2・4・5・6を省略し、比較対象の既知ビットがすべて入力値と一致する解を探します。

## 5. 通常RSとビット単位の修復

通常RSでは、不明なビットが一つでもあるコード語は、語全体の値が分からない「消失」として扱います。部分ビット制約は、その語に残る既知ビットも使います。部分ビット探索は、不明ビットに仮の値を入れて通常RSを再試行します。

例えば8語に1ビットずつ不明があると、通常RSでは8語が消失になります。部分ビット制約なら、残る56ビットを条件として利用できます。

### 通常RSの計算と訂正範囲

RSでは、8ビットの値を、256個の値を持つ有限体GF(256)で計算します。有限体は、加算・減算・乗算と、0以外による除算ができる有限個の値の集合です。GFはGalois Field（ガロア体）の略で、有限体を表します。

受け取ったコード語列から、RSの条件を満たすか調べる検査値である**シンドローム**を求めます。不明な語の位置は入力から分かるため、その情報も使って誤りの位置と訂正値を求めます。訂正後はシンドロームがすべて0になることを確認します。

通常の訂正範囲は、各ブロックについて次の関係で表せます。

`2e + s ≤ r`

`e`は場所の分からない誤り語数、`s`は消失語数、`r`はECC語数です。いずれもコード語単位で数えます。

ECCが10語なら、誤り2語と消失6語は範囲内ですが、誤り3語と消失6語は範囲外です。通常RSで修復できなければ、部分ビット制約やリスト復号なども試します。訂正できた場合は、得られた語列をQR構造と入力条件で検証します。

### 不明ビットを連立一次方程式で求める

RS部分ビット制約では、既知ビットを固定し、不明ビットだけを変数にします。

GF(256)のRS条件は、ビットに分解すると0と1の有限体GF(2)上の線形条件になります。GF(2)の加算は排他的論理和で、二つの値が同じなら0、異なるなら1になります。各不明ビットがシンドロームへ与える影響を列として並べ、次の形の連立一次方程式を作ります。

`A x = b`

- `x`：不明ビットの値
- `A`：各不明ビットがRS条件へ与える影響
- `b`：既知ビットから決まる値

方程式を変形して変数を順に消去し、条件の矛盾、値が決まるビット、自由に選べる変数を求めます。既知ビットが誤っていると矛盾する場合があり、この方法ではその既知ビットを訂正できません。自由変数が`d`個なら、RS条件だけでは`2^d`通りの解があります。自由変数の個数を**自由度**と呼びます。

QRの符号化方式・文字数やバイト数・終端などを追加条件として使い、各ブロックに残る自由度が探索上限以内か確認します。数字などが表現できる値の範囲も検査します。

自由度0なら、選んだ形式と既知ビットを条件とするRSの解が一つに決まります。その解についても、他の候補と同様にQR構造と入力条件を検証します。

### 仮の値を試して消失語数を減らす

部分ビット探索では、不明ビットが1～4個のコード語から、不明数の少ない語を優先して選びます。ブロックごとの上限内で値を割り当て、通常RSを試します。

例えば、不明ビットが2個あるコード語には4通りの値があります。不明ビットに仮の値を入れて8ビットすべてがそろうと、通常RSで扱う消失語数が一つ減ります。これにより、残りの消失や誤りを訂正できる場合があります。

部分ビット探索の上限は、RS部分ビット制約で解を列挙するときの自由度の上限にも使います。

`*`を指定した場合も、まず指定セルを不明のまま修復を試します。内容を復号できなければ、指定セルに`0 / 1`を割り当てて試します。例えば2セルなら、`00 / 01 / 10 / 11`の4通りです。試した値は計算記録に残します。

### 既知bit誤りの追加探索

**既知bit誤りの追加探索**は既定でOFFです。ONにすると、修復開始時に値が分かっていたデータ・ECCビットについて、QR全体で最大1ビットまたは2ビットの誤り位置を探します。上限はブロックごとではなく、すべてのRSブロックの合計です。

まず、不明ビットの値を選ぶことで満たせるRS条件を取り除き、不明ビットの割り当てだけでは解消できない不一致を調べます。反転なし、1ビット反転、設定に応じて2ビット反転の仮説を試し、残る条件と両立するものについて、不明ビットを連立一次方程式で求めます。反転を仮定した後の値にQR構造の条件を加え、ブロックの解を組み合わせて候補を検証します。

この探索は修復開始時の入力から行い、先行する段階の構造補完や`*`への仮置きは引き継ぎません。`*`も不明ビットとして扱います。保護された固定セルは反転の対象外です。データ・ECCの誤り上限、選択したバージョン・向き、ECC・マスクの指定も引き続き適用します。単一セグメントの終端後構造の強制がONなら、そのヘッダーと末尾構造の条件も維持します。OFFなら、反転の仮説ごとに符号化方式や文字数・バイト数を調べ直せます。

通常RSの誤り・消失訂正やリスト復号とは別の方法です。後続のリスト復号は元の入力から独立に探索し、ここで仮定した既知ビットの反転を引き継ぎません。候補には、反転を仮定した位置と、その条件で不明ビットを求めた計算記録を残します。条件を満たす候補が複数得られる場合もあります。

## 6. QRデータの構造を利用する

QRデータは、符号化方式、文字数やバイト数、内容、終端、残り領域の埋め方に規則があります。QRevyは、計算途中で不可能な解を除くためにも、完成した候補を検証するためにも、この構造を使います。

セグメントは、一つの符号化方式で続けて記録されたデータのまとまりです。自動補完では、データが一つのセグメントで構成されていると仮定し、読み取った符号化方式や文字数・バイト数に合う構造を調べます。

### 構造による補完、探索中の制約、最終検証

構造の利用には三つの役割があります。

| 役割 | 処理 |
| --- | --- |
| 誤り訂正前の補完 | 仮定した符号化方式・文字数やバイト数から、不明なビットの値を求める |
| 探索中の絞り込み | RSの自由変数やブロックの組み合わせへ条件を加える |
| 完成後の検証 | データ列全体がQRの規則に従うか確認する |

例えば数字3桁は10ビットで表し、値は0～999です。RSに整合する10ビットでも、1,000以上なら数字3桁としては不正です。

データの終わりを示す終端の後には、8ビットの区切りまで0を入れます。残る領域には、埋め草として16進数`EC`と`11`のコード語を交互に入れます。容量の末尾では、残りのビット数に応じて終端が短くなる場合や省略される場合も確認します。

符号化方式や文字数・バイト数の候補が複数残る場合は、それらの候補すべてで同じ値になるビットを補うことがあります。例えば、調べているどの候補でも、あるビットが終端後の`0`に当たるなら、そのビットを`0`で補います。

### 終端・埋め草の補完と誤り上限

ここでは、終端から埋め草までを「末尾」と呼びます。**単一セグメントの終端後構造を強制する**の設定により、補完の条件が変わります。

| 設定 | 動作 |
| --- | --- |
| OFF | 末尾の既知ビットが規則と6ビット以上一致することを条件に、補完を試します。補完しない探索も行い、複数セグメントの候補も扱います。 |
| ON | 読み取った、または `*` の探索で仮定した符号化方式と文字数・バイト数に従って、末尾を補正します。訂正によってこれらの値が変わる候補は採用しません。 |

OFFでも、符号化方式と文字数・バイト数が分かる場合は、末尾の読み間違いを**データ・ECCの誤り上限**内で訂正できます。どちらの設定でも、誤り数は**修復前の入力との比較**で数え、末尾の訂正も含めます。例えば、末尾2ビット・本文2ビット・ECC2ビットの訂正は合計6ビットなので、上限5ビットでは採用しません。固定セルの保護や、指定したECC・マスクなどの条件も適用します。

### 今回だけ強制して再実行する

内容を復号できた候補がなく、末尾を強制すれば復号できる見込みがある場合は、**今回だけ再実行**を提案します。選択すると、その実行だけ強制をONにします。詳細設定はOFFのままで、実行条件は履歴と保存した作業に残ります。

探索を中断した場合は提案せず、同じ入力・設定で繰り返し提案しません。提案が出ない場合も、詳細設定で手動でONにして試せます。

## 7. リスト復号

リスト復号は、通常RSの訂正範囲を超えて複数の候補を探します。QRevyはGuruswami–Sudan（GS）法、Koetter–Vardy（KV）法、Wu法を使います。

訂正半径は、その試行に渡した値と異なってよいコード語数の上限です。消失語はこの数に含めません。GSとWuは同じ訂正半径について計算量・メモリを見積もり、一方を選びます。KVは部分的に値が分かっているコード語を、重み付きで利用します。

### GS・Wuの訂正半径と候補生成

消失を除いて利用する語数を`n`、データ語数を`k`とすると、通常RSの誤り訂正半径は`floor((n − k) / 2)`です。`floor`は小数点以下の切り捨てを表します。

GS・Wuでは、通常RSの半径より1語、2語、3語多い範囲を、設定した追加探索上限まで検討します。ただし、アプリが訂正半径の上限に使う数学的な条件であるJohnson境界に従い、

`(n − t)² > n(k − 1)`

を満たす半径`t`に限ります。数学的な条件を満たしても、計算量やメモリの上限によって実行しない場合があります。

GSは、コード語の位置と値を二つの変数で表し、読み取った位置・値で所定の条件を満たす多項式を作ります。この操作を補間と呼びます。そこから多項式を0にする関係（根）を求め、コード語列の候補を作ります。

Wuは、誤り位置を表す多項式から位置の候補を求め、訂正値を計算します。

どちらも、その試行の値と異なるコード語数が訂正半径以内か、RS条件を満たすかを再確認します。

不明ビットへ仮の値を置いてから適用する場合もあります。なお不明ビットが残る語は消失として扱います。ここで数える不一致は、その試行に渡した値との違いです。仮の値を含む場合があるため、修復開始時の入力との不一致数とは区別します。

### KVが部分的なコード語を使う方法

KVでは、不明ビット数が`u`のコード語について、既知ビットと両立する`2^u`個の値へ等しい重みを与えます。

例えば`1010?011`なら、両立する値は`10100011`と`10101011`です。それぞれへ基準の重みの半分を与えます。

不明ビットが4個以下の語を重み付けの対象にし、5個以上の語の重みは0にします。この計算上の重みを多重度と呼びます。多重度に応じた条件を満たす多項式を補間し、その根から候補列を求めます。候補の各語が入力の既知ビットと一致する場合、その値に与えた重みを合計し、一致スコアとします。一致スコアが、補間した多項式の次数に基づく必要な値を超えることを確認し、さらにRS条件を検証します。

追加探索上限はGS・Wuの訂正半径を制限します。KVには一致スコアによる条件を使います。

## 8. QR全体の検証と候補の統合

各ブロックの解を組み合わせてデータ列を作ります。各ブロックに複数の解がある場合は、その組み合わせを調べます。途中まで組み合わせたデータ列がすでにQR構造に反するなら、その組み合わせの続きを調べる処理を打ち切ります。

完成したデータ列がQRの構造に従っているかを検証します。「単一セグメントの終端後構造を強制する」が有効な場合は、その条件も検証します。続いて、コード語をQR上の配置へ戻し、訂正を許容していない固定セルと値が一致するか、入力との不一致が誤り上限以内かを確認します。いずれかの条件を満たさない候補は除外します。

検証に通った候補は、内容の最終復号を試します。内容を復号できない場合も、構造検証済みの候補として保持できます。

### 候補の統合と順位

バージョン、ECCレベル、マスク、訂正後のコード語がすべて同じ結果は、一つの候補にまとめます。同じ文字列でも、これらのいずれかが異なれば別候補です。

候補は次の順で比較し、差がなければ次の項目で順位を決めます。

1. 内容を復号できている。
2. 形式情報の不一致が少ない。
3. 形式情報の一致が多い。
4. 既知データ・ECCビットとの不一致が少ない。
5. 比較できた既知ビットが多い。
6. 各ブロックの通常RS訂正余裕のうち、最も小さい値が大きい。
7. 探索で仮置きしたビットが少ない。
8. 訂正対象のコード語が少ない。
9. 消失コード語が少ない。

通常RSの訂正余裕は、その計算について`ECC語数 − 消失語数 − 2 × 誤り語数`です。補完や仮置きの後に計算した余裕は、修復開始時の入力にそのまま通常RSを適用したときの余裕とは異なります。部分ビット制約、既知bit誤り探索、リスト復号を使った候補は、優先順位の判定では訂正余裕を0として扱います。

セルの信頼度は、値の由来、画像の評価、比較対象候補の一致などから求める説明用の指標です。

同じ候補を得た計算方式、同じ入力に対する別計算、別の読み取り試行を区別して記録します。一つの候補に複数の計算記録が対応することがあります。

## 9. 探索の上限と結果の意味

探索には上限があります。一度に仮の値を試す不明ビット数、ブロック間で調べる組み合わせ数、計算時間、作業メモリ、候補や計算記録の保持数を制限します。

リスト復号に使える時間は、1回の修復に含まれるすべてのリスト復号の計算を合わせて10分です。他の方法に使う時間は含みません。リスト復号で許す既知データ・ECCビットとの不一致数は、データとECCの総ビット数に5%を掛けて小数点以下を切り上げた値と、指定した誤り上限のうち、小さい方までです。

既知bit誤りの追加探索には、1回の修復に含まれるすべての形式・読み取り試行を通じて、累計30秒・100万試行の上限があります。他の方法の時間は含みません。部分ビット探索・自由度の上限、ブロック間の組み合わせ数、作業メモリ、候補保持数の制限も適用します。時間または試行数の上限に達した場合は、未探索が残ることと終了理由を表示します。

中断、時間切れ、メモリ不足で探索を止めた場合も、それまでに得た検証済み候補は結果に残します。探索を途中で止めた場合と、見つかった候補や計算記録を保持数の上限により省略した場合は、区別して表示します。

探索完了は、設定と上限に従って予定した処理を終えたことを示します。上限によって調べていない組み合わせがあり得るため、候補がないことだけで修復不能とは判断できず、一つだけ見つかっても他に解がないとは限りません。

RS、QR構造、入力条件の検証に通り、内容を復号できても、元のQRに記録されていた内容と一致する保証はありません。候補の順位やセルの信頼度は、結果を比較・確認するための目安です。KVの重みも含め、これらは正解の確率を表すものではありません。
