# 修復結果の見方

[English](RECOVERY_RESULT_FIELDS.en.md) | 日本語

この文書では、修復結果、診断情報、セルごとの修復理由を説明します。操作方法と設定は[ユーザーガイド](USER_GUIDE.ja.md)、探索順と各方法の適用条件は[QR Repairの修復の仕組み](RECOVERY_STRATEGY.ja.md)を参照してください。

QRコードには、損傷した内容を復元するための誤り訂正符号（ECC: Error Correction Code）が含まれます。リード・ソロモン（Reed–Solomon、RS）符号の検査に通っただけでは、修復した内容の正しさは保証されません。信頼度は説明用の指標であり、正解の確率ではありません。重要な内容は別の資料や手段でも確認してください。

## 最初に結果を確認する

QR構造と指定した入力条件の検証に通ったものを**検証済み候補**、さらにQRデータの最終復号に成功したものを**復号済み候補**と呼びます。QRデータには文字列だけでなく、バイナリデータも含まれます。

| 表示 | 意味 | 確認するもの |
| --- | --- | --- |
| 指定条件を満たす修復候補がN件見つかりました。 | 一覧の候補は検証に通っている。復号の成否は別に示す | 内容、候補間の違い、探索の完了状況 |
| QRのデータ形式を確認しました／文字として表示できないデータです。 | 選択中の候補は構造検証に通ったが、最終復号には失敗した | **データ**とセルの修復理由。QRの選択・出力は可能 |
| 調べた範囲では修復候補は見つかりませんでした。 | 選択できる候補を保持していない | 入力条件、不採用の理由、探索の完了状況 |

修復候補を得られなかった場合、**データ**には不明値（`?`）を含む入力を表示し、結果画像は出力できません。診断に表示される、修復前の部分的に読めた内容も復号結果ではありません。不明ビットや不正な値に達すると表示を止めます。

## 候補と内容

結果一覧には、すべての読み取り試行から得た最大256件の候補を表示します。読み取り試行とは、格子の位置と読み取り条件の一つの組合せで画像を読み取ることです。表示件数は選択できる候補の数であり、保持件数やメモリ量の制限により一覧に含まれない候補がある場合もあります。

同じ修復後のQRは1件と数えます。別の方法や読み取り試行でも同じQRが得られた場合は、**同じQRを得た処理の記録**で確認できます。候補を切り替えると、QR、修復前の入力、診断情報も切り替わります。

「異なる内容」は、表示文字列だけでなくQRに符号化されたデータを比較します。例えば、異なる方法で符号化された2候補がどちらも`ABC`と表示されても、別の内容として数える場合があります。

検証済み候補は、最終復号に失敗しても選択・出力できます。内容のコピーと候補一致の解析は、復号済み候補が対象です。URL（Webアドレス）や連絡先として解釈できる場合も、内容の表示とコピーでは復号した文字列全体を保持します。

内容が複数のQRに分かれている**連結QR（Structured Append）**では、このQRの番号、総数、パリティ（内容全体の確認に使う値）を表示します。QR Repairが扱うのは個々のQRであり、複数QRの連結や、内容全体のパリティ検証は行いません。

## 探索の完了と候補の省略

候補が見つかることと、探索が完了することは別です。

| 表示 | 意味 |
| --- | --- |
| 指定条件・探索仕様の範囲で探索を完了しました。 | 上限への到達による通常の終了も含め、定められた範囲の探索を終えた。数学的に考えられる全候補を調べたとは限らない |
| 未探索の組合せが残っています。 | 中断、時間切れ、作業メモリ不足、内部エラーによって必要な探索を実行できなかった |
| 探索の完了状況を確認できません。 | 完了したかどうかを判断する記録が足りない |
| ほかの候補は省略／候補の省略（保持上限） | 見つかった候補の一部が一覧になく、選択できない。探索が未完了であることとは別の状態 |

リスト復号は、通常のRSの訂正範囲を超えて候補を求める追加探索です。制限時間は**修復1回につき累計600秒（10分）**で、通常の探索時間は含みません。時間切れ、メモリ不足、中断時も、それまでに得た検証済み候補は残ります。探索が完了しても一意性は保証されず、候補がなくても解が存在しないとは限りません。

## 入力との一致とQR設定

| 項目 | 意味 |
| --- | --- |
| バージョン | QRの大きさ。例えば`V3`はバージョン3を表す |
| 誤り訂正レベル（ECCレベル） | `L / M / Q / H`。同じバージョンでは、この順に誤り訂正用のデータが多くなる。修復可否は損傷位置にも依存する |
| マスク | QRデータに適用する模様の番号（`0～7`）。選択したマスクによってセル値の解釈が変わる |
| 形式情報の不一致 | 入力QR内の2か所の形式情報（誤り訂正レベルとマスク）を候補と比較した不一致数 |
| データ・ECC領域の不一致 | 内容と誤り訂正用のデータについての不一致数。QRの機能パターンなど、この領域外の情報は含めない |

不一致数は、手動編集も含めた修復開始時の既知の`0 / 1`と候補を比較します。例えば`3 / 80`は、比較した80ビットのうち3ビットが異なることを示します。不明セルと、`*`の探索で一時的に割り当てた値は比較に含めません。比較できるビットが0個なら、一致は未確認です。

形式情報では、**ECC・マスクの明示指定だけで値が決まる、固定した0/1セル**も比較から除きます。仮指定の値は比較に含めます。固定値の訂正を許容する設定がONでも、この比較除外は維持します。

誤り上限の**0ビット**は、比較対象の既知ビットすべてとの一致を要求します。固定値の保護は別の条件であり、誤り上限を増やしても、保護されている固定値の変更は許可されません。明示したバージョン・ECC・マスクの指定も引き続き適用します。設定の変更方法はユーザーガイドを参照してください。

## 診断詳細

| 区分 | 確認できる内容 |
| --- | --- |
| 今回の設定 | この修復に使った設定 |
| 修復前の状態 | 修復開始時の入力と、通常RSの参考診断 |
| 今回の処理 | 候補を得た方法、仮定、計算記録、および探索全体の記録 |
| 確認結果 | 構造検証、最終復号、入力との不一致、探索の完了状況、省略 |

通常RSの参考診断には、構造に基づく補完や一時的な値の割り当てを行う前の入力を使います。その成否は参考診断についての結果であり、探索全体の結果は**確認結果**で確認します。探索全体の記録には、選択中の候補が得られなかった試行も含みます。

**コード語**は8ビットのまとまりです。RSの計算記録に出てくる**語・シンボル・byte**も、この単位を表します。**RSブロック**は、誤り訂正をまとめて行うコード語の集まりです。不明・訂正コード語数と、修復したセル数は異なります。不明な1ビットを補うだけで、1コード語が確定する場合もあります。

### 診断に表示される方式

方式名は、候補の値を求めた方法を表し、RSブロックごとに異なる場合があります。計算に使った値には、それ以前に構造から補った値や、一時的に割り当てた値も含まれます。

| 方式 | 手掛かりにするもの | 何をするか |
| --- | --- | --- |
| 通常RS | コード語の値と、不明ビットを含む位置 | 通常のRSの範囲で不明なコード語を補い、誤った値を訂正する。不明ビットを一つでも含むコード語は、消失として扱う |
| 部分bit制約 | 既知ビットとRSの条件 | その段階の既知ビットを保ったまま、不明ビットを求める。この方法では、誤った既知ビットは訂正しない |
| bit探索／優先セルのbit探索 | 上限内で選んだ不明ビット | `0 / 1`を割り当て、その後の検査を行う。部分ビット探索では選んだコード語を埋め、優先セルの探索では`*`を使う。試した値は仮定である |
| 構造補完 | モード（符号化方式）、長さ、終端、埋め草などのQRデータの規則 | 調べている構造から決まる値を補う。単一セグメントの仮定に依存する補完もある |
| Guruswami–Sudan（GS）法 | 消失として扱わないコード語の位置と、その値 | 位置と値の関係を表す式から、通常の訂正範囲を超えるRS候補を求める |
| Koetter–Vardy（KV）法 | 既知ビットと両立するコード語の候補値 | 候補値へ計算上の重みを分配し、重み付きの一致が十分な候補を求める。不明ビットの全組合せを試さずに、一部だけ分かっているコード語も利用できる |
| Wu法 | 誤ったコード語があり得る位置 | 誤り位置の組合せを求め、そこから得られる訂正を検査して、通常のRSの範囲を超える候補を探す。Wuは研究者の姓であり、略語ではない |

同じ入力と訂正範囲に対し、計算量やメモリ量の見積もりからGS法かWu法を選びます。方式名は信頼度の順位を示しません。複数の方法で同じ候補が得られても、正しさを独立に証明したことにはなりません。

例えばKV法では、`1010?011`に対する二つの候補値`10100011`と`10101011`へ、同じ計算上の重みを与えます。それぞれの正解確率が50%という意味ではありません。重みは既知・不明ビットから決めており、画像の濃淡を直接使うものではありません。同じ基準の重みなら、不明ビットが多いほど各候補値の重みは小さくなり、曖昧さが大きいコード語には重みを与えない場合があります。入力の既知値の誤りを訂正する場合もありますが、保護された固定`0 / 1`との一致は、別途、候補を採用する条件として守ります。

### 計算記録の用語

| 表示 | 意味 |
| --- | --- |
| 訂正半径 | その試行で使った値と異なってよいコード語数の上限。消失として扱う語は除く。修復したビット数や、元のQRとの差ではない |
| 残存消失 | 補完や一時的な値の割り当ての後も、不明として扱うコード語数。訂正半径内の誤りとは別に数える |
| 追加探索上限：＋1／＋2／＋3 | 残存消失を考慮した通常RSの訂正半径に対し、GS・Wuで追加する範囲の上限。ブロックごとのコード語数で表す。適用条件や時間・メモリの上限により、そこまで調べられない場合もある。KVは独自のスコア条件を使う |
| 通常RS訂正余裕 | その計算で、消失1語につき1、誤り1語につき2をECCの語数から差し引いた値。補完や一時的な値の割り当ての後に計算した値は、修復開始時の入力の余裕を表さない |
| 一致スコア／必要スコア | KV法の重み付きの一致の合計と、その計算で必要な下限。正解確率や、セルに表示する候補一致の件数ではない |
| 多重度／多重度の基準 | GS・KVの計算条件を作るための重み。KVでは基準の重みを、両立するコード語の候補値へ分ける。大きいと計算が増える場合があり、信頼度が高いという意味ではない |
| Y次数 | GS・KVの計算式の次数の上限。計算についての値であり、候補数や正しさを示すものではない |
| Johnson境界 | アプリがGS・Wuで使う訂正半径を制限する数学的な条件。この条件を満たさない試行は省略するが、修復できる解がないことを意味しない |

修復開始時の入力を使う参考診断でも、RSの訂正結果が得られなかった場合の余裕は不明です。部分bit制約とリスト復号には、通常RSの訂正余裕はありません。

試行・完了の回数はブロックの計算回数であり、修復したQRの候補数ではありません。探索全体の記録には、選択中の候補に使わなかった計算も含まれます。計算の省略と中断では意味が異なるため、表示された理由と探索の完了状況を併せて確認してください。

**自由度**は、RSの条件を満たす組合せの中で、独立に選べる不明ビットの数です。この診断では、選択した形式と入力の既知ビットが正しいと仮定します。自由度0は、その前提でRSの解が1通りであることを示し、QRの内容は未検証です。この自由度は修復候補の件数を示すものではありません。検証済み候補がなくても、曖昧さを減らすための確認セルを案内できる場合があります。

候補が不採用になった場合は、表示された理由を確認してください。固定セルとの矛盾ならその編集を、形式情報の上限超過なら形式情報のセル、ECC・マスク指定、形式情報の誤り上限を見直します。追加確認の目安が0ビットでも、既知値の誤りや探索上限によって修復できない場合があります。

## セルの修復理由

**詳細結果を表示**で開くセルの詳細では、入力値、最終値、主な理由、補助根拠を区別します。理由は値を得た方法の説明であり、理由が複数あっても、正しさについて独立した多数決を取ったことにはなりません。

| 修復理由の枠色 | 分類 | 意味 |
| --- | --- | --- |
| 緑 | QR固定構造 | 位置検出パターンや形式情報など、選択したバージョンと形式から値を決めた。その選択が正しいことが前提 |
| 橙 | RS | **RS消失復元**は入力の`?`を補完したこと、**RS誤り訂正**は入力の`0`または`1`を変更したことを示す |
| 紫 | QRデータ制約 | 内容、長さ、終端、埋め草（内容の後の空き領域を埋める値）などの規則から値を補った。仮定したデータ構造に依存する場合がある |
| 赤紫 | ビット単位候補探索 | 上限のある範囲で、不明ビットに`0 / 1`を割り当てて試した |
| 青 | ユーザー編集 | 利用者が値または由来を指定した。固定、仮指定、訂正を許容した固定の違いは**入力**で確認できる |

**補助根拠**は最終値を支持する情報です。後からRSが変更した値は、途中の履歴として表示します。例えば、構造の規則から`0`を補い、RSが`1`へ訂正した場合、先に補った`0`は途中値として記録します。最終値`1`の補助根拠には含めません。

**単一セグメントの仮定**には、対応する詳細設定の有効・無効と、この候補への適用状況を表示します。セグメントとは、一つのモードで符号化されたQRデータのまとまりです。構造に基づく補完がある場合は、この仮定も確認してください。単に**修復**と表示する場合は、より具体的な分類がありません。値が同じまま由来だけが変わったセルは、変更として強調しません。

セル座標`(x,y)`は0始まりです。コード語番号、RSブロック番号、ブロック内の位置、ビット位置は1始まりで、左端がビット1です。**マスク解除後**には修復前後のコード語を表示し、不明ビットを`?`、選択したビットを角括弧で示します。**同じコード語を表示**で、その8セルを強調します。

形式情報のセルでは、役割とビット位置を表示します。計算の説明で2か所の形式情報を比較でき、関連セルのボタンで誤り訂正レベル、マスク番号、訂正ビットの対応セルを強調します。データ領域の**マスク解除**では、形式情報のセルは変わりません。

## セルの評価と候補一致

**入力の評価**は修復前の入力についての値で、手動編集も含む場合があります。**候補の評価**は候補一致などの根拠も考慮します。どちらも説明用の指標であり、正解の確率ではありません。

**候補一致**は、そのセルについて、選択中の候補と同じ値を持つ候補の数です。例えば`12 / 16`は、比較した16候補のうち12候補が、そのセルで一致したことを示します。

比較には、**同じ読み取り試行から得た復号済み候補**の上位最大16件を使い、選択中の復号済み候補を必ず含めます。比較できる候補が2件以上ある場合に表示します。結果一覧の最大256件よりも狭い比較範囲です。

併記する**検証済み全N候補**は、その読み取り試行で保持している復号済み候補の数で、別の試行の候補は含みません。候補を使った追加確認の案内も、比較対象だけについての説明です。`16 / 16`でも、比較外や未発見の候補との一致、そのセルの正しさは保証されません。
