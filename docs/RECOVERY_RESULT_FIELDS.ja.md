# 修復結果の見方

[English](RECOVERY_RESULT_FIELDS.en.md) | 日本語

この文書では、修復結果、診断情報、セルごとの修復理由を説明します。操作方法と設定は[ユーザーガイド](USER_GUIDE.ja.md)、探索順と各方法の適用条件は[QRevyの修復の仕組み](RECOVERY_STRATEGY.ja.md)を参照してください。

QRコードには誤り訂正用のデータ（ECC）が含まれます。リード・ソロモン（Reed–Solomon、RS）符号の検査に通っただけでは、修復した内容の正しさは保証されません。重要な内容は別の資料や手段でも確認してください。

## 最初に結果を確認する

QR構造と指定した入力条件の検証に通ったものを**検証済み候補**、さらにQRデータの最終復号に成功したものを**復号済み候補**と呼びます。QRデータには文字列だけでなく、バイナリデータも含まれます。

| 表示 | 意味 | 確認するもの |
| --- | --- | --- |
| 指定条件を満たす修復候補がN件見つかりました。 | 一覧の候補は検証に通っている。復号の成否は別に示す | 内容、候補間の違い、探索の完了状況 |
| QRのデータ形式を確認しました／文字として表示できないデータです。 | 選択中の候補は構造検証に通ったが、最終復号には失敗した | **データ**とセルの修復理由。QRの選択・出力は可能 |
| 調べた範囲では修復候補は見つかりませんでした。 | 選択できる候補を保持していない | 入力条件、不採用の理由、探索の完了状況 |

修復候補を得られなかった場合、**データ**には不明値（`?`）を含む入力を表示し、結果画像は出力できません。診断に表示される、修復前の部分的に読めた内容も復号結果ではありません。不明ビットや不正な値に達すると表示を止めます。

## 候補と内容

結果一覧には、すべての読み取り試行から得た、選択可能な最大256件の候補を表示します。各試行では格子の位置と読み取り条件の一つの組合せを使います。保持件数やメモリ量の制限により、一覧に含まれない候補がある場合もあります。

同じ修復後のQRは1件と数えます。**このQRを得た計算方法**で、そのQRが得られた方法と読み取り試行を確認できます。

「異なる内容」は、表示文字列だけでなくQRに符号化されたデータを比較します。例えば、異なる方法で符号化された2候補がどちらも`ABC`と表示されても、別の内容として数える場合があります。

内容のコピーと候補一致の解析は、復号済み候補が対象です。URL（Webアドレス）や連絡先として解釈できる場合も、内容の表示とコピーでは復号した文字列全体を保持します。

内容が複数のQRに分かれている**連結QR（Structured Append）**では、このQRの番号、総数、パリティ（内容全体の確認に使う値）を表示します。QRevyが扱うのは個々のQRであり、複数QRの連結や、内容全体のパリティ検証は行いません。

## 探索の完了と候補の省略

候補が見つかることと、探索が完了することは別です。

| 表示 | 意味 |
| --- | --- |
| 指定条件・探索仕様の範囲で探索を完了しました。 | 上限への到達による通常の終了も含め、定められた範囲の探索を終えた。数学的に考えられる全候補を調べたとは限らない |
| 未探索の組合せが残っています。 | 中断、時間切れ、作業メモリ不足、内部エラーによって必要な探索を実行できなかった |
| 探索の完了状況を確認できません。 | 完了したかどうかを判断する記録が足りない |
| ほかの候補は省略／候補の省略（保持上限） | 見つかった候補の一部が一覧になく、選択できない。探索が未完了であることとは別の状態 |

リスト復号の制限時間は**修復1回につき累計600秒（10分）**で、通常の探索時間は含みません。時間切れ、メモリ不足、中断時も、それまでに得た検証済み候補は残ります。探索が完了しても一意性は保証されず、候補がなくても解が存在しないとは限りません。

## 入力との一致とQR設定

| 項目 | 意味 |
| --- | --- |
| バージョン | QRの大きさ。例えば`V3`はバージョン3を表す |
| 誤り訂正レベル（ECCレベル） | `L / M / Q / H`。同じバージョンでは、この順に誤り訂正用のデータが多くなる。修復可否は損傷位置にも依存する |
| マスク | QRデータに適用する模様の番号（`0～7`）。選択したマスクによってセル値の解釈が変わる |
| 形式情報の不一致 | 入力QR内の2か所の形式情報（誤り訂正レベルとマスク）を候補と比較した不一致数 |
| データ・ECC領域の不一致 | 内容と誤り訂正用のデータについての不一致数。QRの機能パターンなど、この領域外の情報は含めない |

不一致数は、手動編集も含めた修復開始時の既知の`0 / 1`と候補を比較します。例えば`3 / 80`は、比較した80ビットのうち3ビットが異なることを示します。不明セルと、`*`の探索で一時的に割り当てた値は比較に含めません。比較できるビットが0個なら、一致は未確認です。

形式情報では、**ECC・マスクの明示指定だけで値が決まる、固定した0/1セル**も比較から除きます。仮指定の値は比較に含めます。固定値の訂正を許容する設定がONでも、この比較除外は維持します。

誤り上限の**0ビット**は、比較対象の既知ビットすべてとの一致を要求します。誤り上限を増やしても、保護されている固定値の変更は許可されません。明示したバージョン・ECC・マスクの指定も引き続き適用します。

## 診断詳細

| 区分 | 確認できる内容 |
| --- | --- |
| 今回の設定 | この修復に使った設定 |
| 修復前の状態 | 修復開始時の入力と、通常RSの参考診断 |
| 今回の処理 | 候補を得た方法・計算記録、リスト復号の実行状況、単一セグメントの仮定の適用状況 |
| 確認結果 | 構造検証、最終復号、入力との不一致、探索の完了状況、省略 |

通常RSの参考診断には、構造に基づく補完や一時的な値の割り当てを行う前の入力を使います。参考計算は、その入力・条件についての結果です。一つの参考計算の失敗から、探索全体の失敗原因は断定できません。

候補が得られなかった場合、**今回の処理**に探索結果と完了状況を表示します。探索全体の記録がない場合は、参考診断の入力の探索が完了していても、全体の完了状況は不明です。

**コード語**は8ビットのまとまりです。RSの計算記録に出てくる**語・シンボル・byte**も、この単位を表します。**RSブロック**は、誤り訂正をまとめて行うコード語の集まりです。不明・訂正コード語数と、修復したセル数は異なります。不明な1ビットを補うだけで、1コード語が確定する場合もあります。

### 診断に表示される方式

方式名は、候補の値を求めた方法を表し、RSブロックごとに異なる場合があります。計算に使った値には、それ以前に構造から補った値や、一時的に割り当てた値も含まれます。

| 方式 | 意味 |
| --- | --- |
| 通常RS | 通常のRSの範囲で不明なコード語を補い、誤った値を訂正する。不明ビットを含むコード語は消失として扱う |
| 部分bit制約 | その段階の既知ビットを保ったまま、不明ビットを求める。誤った既知ビットは訂正できない |
| bit探索／優先セルのbit探索 | 選んだ不明ビットに`0 / 1`を割り当て、その後の検査を行う。優先セルの探索では`*`を使う。試した値は仮定である |
| 構造補完 | モード、長さ、終端、埋め草など、調べているQRデータの構造から決まる値を補う。単一セグメントの仮定に依存する補完もある |
| Guruswami–Sudan（GS）法 | 値が分かっているコード語の位置と値から、通常の訂正範囲を超えるRS候補を求める |
| Koetter–Vardy（KV）法 | 既知ビットと両立するコード語の候補値に重みを付け、重み付きの一致が十分な候補を求める。重みは計算用の値であり、確率や画像の明るさではない |
| Wu法 | 誤り位置の組合せと、そこから得られる訂正を検査し、通常の訂正範囲を超える候補を探す |

方式名は信頼度の順位を示しません。複数の方法で同じ候補が得られても、正しさを独立に証明したことにはなりません。

### 計算記録

「このQRを得た計算方法」では、複数の方法をA・Bなどで区別します。「セルの説明に使用」と付いた方法が、セルごとの補完根拠に対応します。詳細にはRSブロックごとの計算値を示します。QR全体の方法数、ブロック内の別計算数、別の読み取り試行数はそれぞれの件数であり、追加の修復候補数ではありません。保持上限による記録の省略も表示します。

「補完なしでも同じQR」は、入力・形式・設定・優先セルへの仮置きなどの条件が一致し、補完しない別の計算でも同じQRが得られた記録があることを示します。計算途中には不明値の補完や既知値の変更があり得ます。補完記録はマスク解除後の前後の値を示し、補完前の値には優先セルへの仮置きも反映します。方法間の比較は、処理の順序を表すものではありません。

「リスト復号の実行状況」では、記録された実行状態・試行回数・所要時間を常時表示します。「計算の詳細を開く」で、方式・訂正半径ごとの内訳、結果の再利用、省略理由を確認できます。この詳細は実行状態にかかわらず最初は閉じています。回数と時間はリスト復号についての値です。試行・完了の回数は、修復したQRの候補数ではなく、ブロックの計算回数です。

候補が得られず、単一セグメントの仮定がONだった場合は、「単一セグメントの仮定の適用状況」で、その仮定を適用できたかを別に表示します。

これらの見出しの括弧内は、記録の対象範囲です。「探索全体」には、選択中の候補が得られなかった試行も含みます。「選択候補の入力」「参考診断の入力」は、探索全体の記録がなく、対象の入力だけの記録であることを示します。計算の省略と中断では意味が異なるため、理由と探索の完了状況を併せて確認してください。

### 計算記録の用語

| 表示 | 意味 |
| --- | --- |
| 訂正半径 | その試行で使った値と異なってよいコード語数の上限。消失として扱う語は除く。修復したビット数や、元のQRとの差ではない |
| 残存消失 | 補完や一時的な値の割り当ての後も、不明として扱うコード語数。訂正半径内の誤りとは別に数える |
| 追加探索上限：＋1／＋2／＋3 | 残存消失を考慮した通常RSの訂正半径に対し、GS・Wuで追加する範囲の上限。ブロックごとのコード語数で表す。適用条件や時間・メモリの上限により、そこまで調べられない場合もある。KVは独自のスコア条件を使う |
| 通常RS訂正余裕 | ECCの語数 − 消失語数 − 2 × 誤り語数。補完・仮置き後の値は、修復開始時の入力の余裕を表さない。訂正結果が得られなければ不明。部分bit制約とリスト復号には通常RSの余裕はない |
| 一致スコア／必要スコア | KV法の重み付きの一致の合計と、その計算で必要な下限。正解確率や、セルに表示する候補一致の件数ではない |
| 多重度／多重度の基準 | GS・KVの計算条件を作るための重み。KVでは基準の重みを、両立するコード語の候補値へ分ける。大きいと計算が増える場合があり、信頼度が高いという意味ではない |
| Y次数 | GS・KVの計算式の次数の上限。計算についての値であり、候補数や正しさを示すものではない |
| Johnson境界 | アプリがGS・Wuで使う訂正半径を制限する数学的な条件。この条件を満たさない試行は省略するが、修復できる解がないことを意味しない |

**自由度**は、選択した形式と入力の既知ビットが正しいと仮定し、RSの条件を満たしながら独立に選べる不明ビットの数です。自由度0は、その前提でRSの解が1通りであることを示し、QRの内容は未検証です。修復候補の件数ではありません。

検証済み候補がなくても、追加確認するセルの案内が出る場合があります。目安が0ビットでも、既知値の誤りや探索上限によって修復できない場合があります。不採用の理由には、固定した編集や形式情報の不一致上限など、見直す条件が示されます。

## セルの修復理由

セルの詳細では、入力値、最終値、主な理由、補助根拠を区別します。理由は、その値を得た方法の説明です。

| 修復理由の枠色 | 分類 | 意味 |
| --- | --- | --- |
| 緑 | QR固定構造 | 位置検出パターンや形式情報など、選択したバージョンと形式から値を決めた。その選択が正しいことが前提 |
| 橙 | RS | **RS消失復元**は入力の`?`を補完したこと、**RS誤り訂正**は入力の`0`または`1`を変更したことを示す |
| 紫 | QRデータ制約 | 内容、長さ、終端、埋め草（内容の後の空き領域を埋める値）などの規則から値を補った。仮定したデータ構造に依存する場合がある |
| 赤紫 | ビット単位候補探索 | 上限のある範囲で、不明ビットに`0 / 1`を割り当てて試した |
| 青 | ユーザー編集 | 利用者が値または由来を指定した。固定、仮指定、訂正を許容した固定の違いは**入力**で確認できる |

**補助根拠**は最終値を支持する情報です。例えば、構造の規則から`0`を補い、RSが`1`へ訂正した場合、先に補った`0`は途中の履歴としてのみ表示します。

**単一セグメントの仮定**には、その設定の有効・無効と、この候補への適用状況を表示します。セグメントとは、一つのモードで符号化されたQRデータのまとまりです。単に**修復**と表示する場合は、より具体的な分類がありません。値が同じまま由来だけが変わったセルは、変更として強調しません。

セル座標`(x,y)`は0始まりです。コード語番号、RSブロック番号、ブロック内の位置、ビット位置は1始まりで、左端がビット1です。**マスク解除後**には修復前後のコード語を表示し、不明ビットを`?`、選択したビットを角括弧で示します。

形式情報のセルでは、役割、ビット位置、2か所の形式情報の比較を確認できます。データ領域の**マスク解除**では、形式情報のセルは変わりません。

## セルの評価と候補一致

**入力の評価**は修復前の入力についての値で、手動編集も含む場合があります。**候補の評価**は候補一致などの根拠も考慮します。どちらも説明用の指標であり、正解の確率ではありません。

**候補一致**は、そのセルについて、選択中の候補と同じ値を持つ候補の数です。例えば`12 / 16`は、比較した16候補のうち12候補が、そのセルで一致したことを示します。

比較には、**同じ読み取り試行から得た復号済み候補**の上位最大16件を使い、選択中の復号済み候補を必ず含めます。比較できる候補が2件以上ある場合に表示します。結果一覧の最大256件よりも狭い比較範囲です。

併記する**検証済み全N候補**は、その読み取り試行で保持している復号済み候補の数で、別の試行の候補は含みません。候補を使った追加確認の案内も、比較対象だけについての説明です。`16 / 16`でも、比較外や未発見の候補との一致、そのセルの正しさは保証されません。
