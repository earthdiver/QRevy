# 修復結果情報の読み方

[English](RECOVERY_RESULT_FIELDS.en.md) | 日本語

メイン画面の内容表示と診断詳細は、修復候補の生成過程と整合性を説明します。信頼度は統計的確率ではなく、Reed–Solomon（RS）成功だけで正しさを保証するものでもありません。

漢字・Hanziの不正な文字コードは、RSが整合していても構造検証で棄却します。文字化けを置換した文字列を成功結果にはしません。バイトモードのバイナリは別扱いです。

## 最初に状態を判定する

| 状態・警告 | 意味 | 最初に確認するもの |
| --- | --- | --- |
| 修復成功 | QRデータ構造と最終復号まで成立した候補が1件以上ある | 復号内容、異なる内容の件数、候補一致、探索上限警告 |
| 修復未完了 | RSに整合する候補はあるが、QRデータ検証または最終復号まで成立していない | 形式情報、バージョン／幾何、部分診断、失敗理由 |
| 修復失敗 | 形式条件などでRSへ進めなかったか、実行した探索内でRS整合候補を得られなかった | 最初に失敗したブロック、消失容量不足ビット、既知ビットとの矛盾 |
| 組合せ／展開ノード上限 | 候補空間の一部を残して探索を停止した | 候補数を一意性と解釈せず、設定や追加確認セルを見直す |
| 候補保持の資源上限 | 32 MiBの計算上の保持予算へ達した | 表示結果と一致数が保持済み候補だけを対象とする点 |

### 短い読取り例

たとえば「修復成功」で検証済み候補が3件、異なる内容が2件、あるセルの候補一致が`2 / 3`なら、少なくとも1件はそのセルで異なる値を持ちます。選択中の内容だけを正解と決めず、そのセルの元画像と修復理由を確認します。反対に`3 / 3`でも、未保持・未探索候補まで含む一意性の証明ではありません。

## 結果と件数

「候補保持の資源上限」は、リクエストで共有する予算に達して以降の探索を止めたことを示します。既に検証できた結果は表示できますが、件数・候補一致の対象は保持済み結果だけです。修復成功時もこの注意が適用されます。セル別説明は参照時に生成します。予算の対象範囲は[修復戦略](RECOVERY_STRATEGY.ja.md)の6節を参照してください。

「修復成功」は、終端・埋め草を含むQRデータ構造検証とZXingによる最終復号を通過した結果があることを示します。元の内容と同一である証明ではありません。旧表示の `Payload parse: ✓`、`Text: ✓`、`RS: ✓` は現在の独立した表示項目ではありません。

同じ幾何内でバージョン、ECCレベル、マスク、訂正後コード語列が同一の結果は1件にまとめます。構造制約あり／なしなどの経路は、それぞれの診断値・セル由来を保持します。「同じ復元結果への探索経路」に経路数と経路別の制約・探索ビット数を表示します。通常の診断値とセルの理由は、順位が最も高い経路1のものです。

「異なる内容」はデータコード語列で区別します。表示文字列が同じでも、コード語列が異なれば別内容として数える場合があります。結果切り替えとPNG保存の候補選択は上位256件までです。これは表示上限であり、探索の網羅性を意味しません。

復号された文字列は、URL・メール・SMS・連絡先などとして解釈できる場合も、解析した項目に加えて元の文字列全体を表示します。無言で切り詰めたり、一部の項目だけに置き換えたりしません。内容のコピーも同じ文字列全体を保持します。

QRデータ未検証の場合は「修復未完了」または「修復失敗」と診断を表示し、結果行列を未検証の訂正値で上書きしません。「データ」画面も修復前を初期表示し、元の部分コード語を `?` 付きで表示します。修復後へ切り替えても未検証の訂正済みbyte列は表示しません。未検証候補や失敗結果では結果PNGを保存できません。調査用の入力画像は、修復設定の詳細画面からデバッグ用入力画像として保存できます。

同じRSブロック訂正値を通常RSと部分ビット制約の両方で得た場合、訂正値は1件のまま、各経路の訂正対象・列挙対象・探索ビット数・RS余裕を保持します。診断ではRSブロックごとに経路数を示し、経路1を代表とします。セルの主理由と通常RS余裕は代表経路を説明し、別経路は補足として表示します。ブロック経路数の積をQR全体の経路数や結果数には加算しません。

## 修復前の部分診断

部分診断は未検証の入力情報であり、復号成功を意味しません。先頭セグメントについて、数字・英数字・バイト・漢字モードでは、モードと文字数／バイト数、および先頭から連続して読み取れる本文を表示します。不明ビットや不正な文字値に達すると本文表示を止めます。

Hanziでは、モードの後にある4ビットのサブセット指示子を先に読みます。GB2312を示す値1の場合だけ、その後の文字数を表示します。指示子が欠損・不明・非対応なら、その状態を表示して文字数は読み取りません。Hanziの本文の部分表示には対応していません。最終修復候補のHanzi検証・復号とは対応範囲が異なります。

## メイン画面の内容表示

| 項目 | 意味 |
|---|---|
| 誤り訂正レベル | `L / M / Q / H`。同じバージョンではこの順にECCコード語が多くなります。復元可否は破損位置とコード語配置に依存します。 |
| マスク | `0～7`。セルをマスク解除してコード語を抽出し、訂正後に再適用して結果行列へ戻します。 |
| 形式情報の誤り | 候補のBCH形式情報との不一致数／比較対象の既知ビット数。ECC・マスク指定によって値が決まり、かつ手動0/1で入力された形式セルは比較から除外します。 |
| データ・ECCの誤り | 修復前入力の既知データ・ECC ビットと、訂正後コード語にマスクを再適用した値との不一致数／比較ビット数。 |

ECCとマスクの両方を明示して形式が1候補に限定された場合、形式情報の誤り上限は適用しません。QRデータ未成立の試行間では、形式情報の不一致が少ないことをRS成功より優先します。

データ・ECCの比較には `?`、一時的な `*` の仮置き値、機能モジュール、残余ビットを含めません。データ・ECCの誤り上限は指定値以下の候補だけを残します。`0bit` は完全一致です。「固定セルの0/1と矛盾する復元候補を許容する（仮指定セルと同じ扱い）」は初期状態でOFFで、固定セルと矛盾する候補を別途棄却します。ONでは固定の指定と入力値を保持したまま訂正を許容します。仮指定セルはどちらの設定でも訂正可能です。訂正には形式情報・データ／ECCの誤り上限が適用され、明示したECC・マスク・バージョン指定と、固定セルとの指定競合の検査は維持します。

## 診断詳細

診断は、実行時の設定、修復前の入力、処理、確認結果を分けて表示します。データ・ECCの不一致上限が0bitの場合、候補の計算には部分bit制約を使います。採用できる候補は、修復開始時のデータ・ECCの既知bitとすべて一致するものに限り、不明bitの補完はできます。固定セルとの矛盾を許容しても、この上限は適用されます。途中の構造補完では既知の末尾bitを変更する場合があるため、この保証は採用する結果についてのものです。

修復前の入力の欄には、参考診断の対象となる型番・ECC・マスク・幾何を明記します。通常RSは、データ・ECCの上限が0bitの場合も、構造補完やbit探索を加える前の入力に対して別途評価します。ブロックごとに、訂正結果あり、不明bitを含むコード語数がECC数を超えるため計算省略、計算したが訂正結果なしを区別します。診断情報がない場合は記録なしと表示し、未実行とは判断しません。RSの結果だけでQRの内容が正しいとは判断できません。

最終結果の説明は、形式・幾何・読み取り条件を通じた診断の集計に基づきます。代表的な失敗1件の理由を探索全体の理由として表示しません。固定セルや形式の矛盾は、許可された入力全体について確認できた場合だけ全体の理由として表示します。「不一致上限（0bit）を満たすRS候補はありません」は、すべての許可形式で初期入力の条件が両立しないと確認できた場合に限ります。構造補完や優先仮置きだけの失敗、記録不足、未確認の入力からは断定しません。探索上限では、候補がないと断定せず未探索の組合せが残っていることを説明します。

通常の消失復号と列挙が同じブロック解を得た場合も別経路を保持します。経路1は従来RS余裕が大きい、探索ビットが少ない、対象シンボルが少ない、ペナルティが小さい順です。探索順用の最小ペナルティが別経路に由来しても、表示する余裕とセル説明は経路1の値です。

### 幾何

「手動射影」は指定四隅を用いた射影モデル、「射影変換」は位置合せパターンの画像証拠による補正を含むモデルです。論理向きとバージョンは保持します。「左上基準」等は幾何の基準であり、ペイロードの読み取り方向ではありません。`V<version>` はQRバージョンで、一辺は `17 + 4 × version` セルです。

### 消失コード語: 修復時 / 入力時

- 入力時：元入力で1ビット以上が不明だったコード語数。
- 修復時：その経路の優先0/1仮置きと構造制約を適用した後、RS処理前に不明ビットが残るコード語数。

差を8倍して修復ビット数にはできません。通常の部分ビット列挙で追加確定したコード語数も、この差には含まれません。

### RS訂正シンボル／RS余裕

RS訂正シンボルは訂正対象のコード語位置数で、消失と未知位置の誤りを含み得ます。RS部分ビット制約の経路では、不明ビットを含んでいたコード語位置を対象として数えます。

通常のRS余裕は、各ブロックの `ECCシンボル数 − RSに渡した消失数 − 2 × 未知位置の誤り数` の最小値です。通常の部分ビット列挙後の消失数を使用し、0は通常RSの容量限界です。RS部分ビット制約を使ったブロックがある場合は「算定対象外（部分bit制約を使用）」と表示します。二進のrankや自由度をシンボル訂正余裕へ読み替えません。

### 構造制約で確定／既知構造との一致

「構造制約で確定」は、その経路で構造制約が設定したビット数です。単一セグメント強制がONなら既知ビットの置換も含みます。後でRSが覆した仮置きも処理履歴として含むため、最終値を支持した制約ビット数とは限りません。

「既知構造との一致」は、終端・バイト境界・`0xEC / 0x11` 埋め草について既知ビットが一致した数です。修復ビット数ではなく、旧表示の `e=` に相当します。

### 優先0/1探索／部分ビット探索

「優先0/1探索」は元入力では不明だった `*` セルを明示的に列挙したビット数です。通常経路だけで成功した場合は記録しません。

「部分bit探索」は、通常の部分コード語列挙では列挙対象ビット数、RS部分ビット制約では列挙した自由変数数を、各ブロックについて合計したものです。復元セル数でも試行回数でもありません。両経路ではセルの由来表示も異なります。

### RS部分ビット制約

未知ビット数、独立制約のrank、自由度、全解共通で確定するビット数を表示します。指定形式と入力の既知データ・ECCが正しいという条件付き診断で、構造制約・一時的な優先割当ての適用前、QRペイロード未検証の状態を対象とします。

自由度0はこの前提でのRS一意解です。矛盾する場合は「完全一致解なし」と表示し、誤り数は推測しません。自由度が列挙上限を超える場合も、解が存在しないという意味ではありません。

QR組合せ探索の診断は成功時にも表示します。成功後の探索窓終了・組合せ数上限・展開ノード数上限を区別し、いずれかの試行に未探索の組合せが残れば、制約なし再試行が完走してもその情報を保持します。候補数は探索済み範囲で検証できた数です。「実行した試行内で完走」は形式・幾何・解空間全体の網羅性を意味しません。

## 失敗理由と追加確認

探索全体の理由では、形式情報の固定セルと明示したECC・マスク指定の矛盾、データ・ECC以外の固定セルとQR構造の矛盾、計算した候補が固定セルや不一致上限を満たさない場合を区別します。優先探索の一時的な仮置きとの矛盾は、手動入力の固定セルとの矛盾として表示しません。

RSの訂正容量と訂正結果は、形式ごとの参考診断に表示します。部分bit探索とQR組合せ探索の上限は、探索上限の説明として表示します。ブロック番号は1始まりです。

消失容量不足ビット数は、各ブロックの消失数をECCシンボル数以下へ減らすために最低限確定する必要があるビット数です。案内でこの値を使う場合、0でも既知ビットの誤りや探索制限によって失敗し得ます。自由度とは異なる尺度です。

検証済み候補がなくても、矛盾のない曖昧なRS解空間があれば、条件付きで自由度を1ビット減らす確認セルを案内できます。これは検証済みQR候補の件数ではありません。

形式情報の誤り上限によって許可された形式が全て除外された場合は、RSを試行せず、形式上限超過として診断します。最も不一致の少ない許可形式の不一致数・比較対象の既知ビット数・指定上限を表示します。形式セルやECC・マスク指定を確認し、必要なら形式情報の上限を見直してください。ECC・マスクを両方指定した場合の上限回避と、手動値との矛盾検査は従来どおりです。

## 連結QRとFNC1

連結QRはStructured Appendを指します。

連結QRでは、内容プレビューと成功表示に、このQRの番号（表示は1始まり）・総数・パリティを表示します。「修復成功」はこのQRについての結果で、連結内容全体の完成やパリティ検証済みを意味しません。連結QRの本文はマスクや伏字にせず表示し、内容のコピーは復元した文字列全体を保持します。FNC1第2位置のアプリケーション識別子は、本文に含めず別項目に生の8ビット値を10進数で表示します。

## セル信頼度と候補一致

候補一致と確認セルの案内には、重複を除いた検証済み候補だけを使います。比較用行列は上位16件までで、選択中の検証済み候補が範囲外なら末尾をその候補へ置き換えます。

「候補一致」は比較対象件数と検証済み全件数を併記します。比較範囲が一部なら、候補分岐・情報利得の案内もその範囲に限ることを明記します。比較対象が一致しても、未比較候補や未探索の別解まで一致する保証ではありません。

各セルの理由と途中履歴は[復号・修復理由の読み方](REPAIR_REASONS.ja.md)を参照してください。
