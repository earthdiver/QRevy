# 初期グリッド推定とFinder自動設定

Android の新規画像取り込み時に、ZXing-C++ 3.1.1 の四隅検出、既存の周期推定、2つのFinderによる補助推定を順に試す。
格子数・境界からセル中心への変換と候補検証は `shared`、JNI 呼び出しは Android 側に置いた。
iOS のネイティブアダプターは未実装。

## 動作

1. 既存ワーカースレッドで ZXing-C++ を実行。通常の Model 2 QR に限定し、デコード失敗時の境界も受け取る。
2. 単一の境界に対し、バージョン1〜40・論理回転4通りを検査する。有限座標・画像範囲内・凸四角形を要求。
3. Finder とタイミングパターンの不一致率がそれぞれ20%以下であることを要求する。重み0.55/0.45で順位付けし、次候補との差が0.03未満なら曖昧として採用しない。これらは構造上のヒューリスティックで、確率ではない。
4. 採用できなければ、既存の `GridPeriodicityEstimator` をそのまま呼ぶ。統合できない複数境界、JNIロード失敗・実行例外でも周期推定を使う。周期推定も失敗すれば2つのFinderによる補助推定を試す。ただし、ネイティブ側が複数境界を返した場合は補助推定を行わない。すべて失敗すれば既定値から手動設定へ進む。
5. 推定したグリッドを既存の修復前設定へ渡し、利用方式とバージョンを取り込み履歴に記録する。厳しい構造・位置検証を満たした場合はFinderの位置・役割と論理グリッドを自動設定し、それ以外は従来の確認操作に従う。

複数境界は上記の検証をそれぞれに適用する。バージョン・論理向きが一致し、対応する四隅がすべて0.25モジュール以内なら同じQRとしてまとめる。許容距離は各隅に隣接する辺から求めた両候補の最小モジュール幅を使い、全ペアで一致を要求する。未検証・別寸法・別向き・離れた候補があれば統合しない。代表は自動設定条件を満たす候補を優先し、他候補との四隅の距離総和が最小のものを決定的に選ぶ。平均座標は作らず、重複数を確度に加算しない。

ZXing-C++ の復号文字列は修復結果に使わない。推定格子を復元成功の証明にはしない。
変更箇所は新規画像の初期設定で、復元・再読み込み時の手動セル編集、固定制約、濃淡設定、通常読み取り、セッション形式は変更しない。
反転検出は追加していない。既存の反転設定を引き続き使用する。
複数 QR の選択 UI は追加しておらず、その場合の周期推定による初期値もユーザーが確認する。

## 依存・配布

公式 Maven Central の `io.github.zxing-cpp:android:3.1.1` を固定指定。
POM上の推移依存 CameraX core 1.5.2 / Kotlin stdlib 2.3.20 は、既存プロジェクトの上位バージョンへ解決される。

新しい通信権限・外部送信・署名設定は追加していない。

## 高一致時のFinder自動設定

ZXing-C++ 由来の初期グリッドに限り、以下をすべて満たす場合は左上・右上・左下の位置と役割を設定する。

- 3つの Finder それぞれで49セル中の不一致が2セル以下。
- 各 Finder の白い区切り15セル中の不一致が1セル以下。
- タイミングパターンの不一致率が5%以下。
- 別バージョン・回転の候補とのスコア差が0.08以上。グリッド採用条件を満たさなかった候補も比較に含める。
- 各辺の平均モジュール幅が2画素以上。
- Finder の各セルについて中心から上下左右に0.25セルずらして再確認し、各位置で不一致が2セル以下。

これらは自動設定のための保守的な判定条件で、統計的な確率ではない。
最後の条件は、セル中心だけで一致してもファインダーの位置がずれるケースを避けるために追加した。
位置は射影変換で算出し、各役割を格子の論理座標に対応付ける。文字列の復号・RS成功を採用条件には使わない。
周期推定由来の格子、条件を満たさない画像、統合できない複数境界ではこの自動設定を行わない。2つのFinder由来の格子には後述の別条件を用いる。

自動設定したことを取り込み履歴へ記録する。設定した座標は格子の制約として保存・復元されるが、セルを手動指定に変更する処理ではない。
画面のFinder欄で「解除」を押して緑のFinderをタップすると個別に解除できる。
設定済みのFinderをすべて解除すると論理的な向きも未確定に戻り、別の役割で指定し直せる。
解除時に四隅・既存セル編集を消去しない。解除して保存した後の再表示でも勝手に自動設定し直さない。
新規画像取り込み時のみ推定し、保存済み設定の読み込みに再推定を差し込まない。

## 大きな遮蔽・背景を含む画像の四隅推定

通常のModel 2検出と画像全体の周期推定の両方が失敗する場合に、既存の個別Finder検出と
`GeometryFitter.twoFinderHypotheses` を使う補助経路を追加した。
残った2つのFinderの幅・軸方向・模様を照合し、タイミングパターンによる役割自動設定、
または独立した右下の位置合わせパターンによる四隅の仮設定を試す。取り込み履歴には「2つのFinderから推定」と記録する。

大きな黒い遮蔽物と周辺の文字があると、QR内部の格子周期が残っていても画像全体の黒画素の範囲は
QRの外接領域と一致しない。この場合、全体範囲に依存しない局所Finderの組み合わせが有効になる。
既存の周期推定自体の数式・採用条件は変更していない。

この補助経路はV2以上、概ね相似変換で扱える画像に限定する。強い透視変形まで2点で解決するものではない。
両経路でモジュール幅の一致、90度を同一視した軸方向、各Finderの複数点照合を要求する。
独立した候補が同程度に一致する場合は採用しない。ネイティブ側が複数の境界を返した場合にも適用しない。
V1やFinderが1つだけの画像ではこの経路を使わず、既存の手動指定・復元を残す。

対角の2つのFinderについては、横・縦のタイミングパターンから役割を判定する。
位置合わせパターンがなくても、次の条件がすべて成立すれば観測した右上・左下だけを自動設定する。

- 各Finderの黒白輝度の中央値で濃淡を校正し、その差が64以上。差の30〜70%の中間帯は不明として扱う。
- 各タイミング軸で8セル以上、全長の60%以上が判定可能で、黒白が各3セル以上。不一致率は5%以下。
- 中心と上下左右0.2モジュールの5位置すべてで上記条件を満たす。
- 各Finderの白い区切りも5位置で照合し、不一致は各1/15以下。
- 各軸・各位置の最大値を使った `(不一致数 + 不明数 × 0.5) / 全セル数` の評価で、次候補との差が0.12以上。
  比較にはFinder検証を通過したすべての役割・バージョン候補を含め、タイミング条件を満たさない候補も除外しない。

これらは確率ではなく保守的な判定条件。V1の各軸5セルでは必要な証拠量を満たさない。
隠れた左上は未設定のままとし、観測した2点は既存の「解除」で個別に取り消せる。
タイミング条件を満たさない場合は、従来の5×5位置合わせパターンによる仮設定を試す。
この仮設定では役割は設定せず、見えているFinderの役割を画面で確認・指定する。
復元文字列の正しさは別途検証が必要であり、四隅の推定成功だけでは復元成功としない。

回帰テストは添付画像をコピーせず、独立した合成構造から作成した。
V2/V4/V7・90度回転・上側の大きな遮蔽・QR外の不規則な暗い模様で従来の周期推定が失敗する状況を再現し、
新しい経路で四隅が正解から1.5画素未満になることを確認する。
タイミングの証拠も位置合わせパターンもない画像・V1・一様画像を拒否するテストも追加した。
外部画像の診断は `tools/detector-study/inspect_image.py --image` に明示的なパスを渡した場合だけ実行する。
添付画像・加工画像・ユーザー固有のファイル名やパスをリポジトリに保存しない。

役割自動設定の追加前に行った検証では、既存の合成264画像の四隅・役割の出力が補助推定追加前と完全一致した。
2点の役割自動設定は、独立した合成画像のV2/V4/V7×4回転、位置合わせパターン欠損、部分的な不明セルで検証する。
片軸のみ・証拠不足・位相違い・位置ずれで不安定なタイミング・反対側にも同じタイミングがある画像では自動設定を拒否する。
Android画面では2点とも解除し、セル編集を保って保存・再表示できることを確認する。
ビルド・テストの最終結果は「ビルド検証記録」にまとめた。Android実機上のJNI実行は未確認。

## 重複境界の統合の検証

独立した合成画像で、V1/V3/V7×4回転の微小な境界ずれと同一候補の重複を統合できることを確認した。
境界の開始隅・入力順に依存せず、離れた2つのQR、寸法・論理向きの違い、一隅だけのずれ、
連鎖的なずれ、未検証境界の混在は統合しない。自動設定条件を満たさない候補は重複しても自動設定しない。
既存の合成264画像では保存済み検出座標を再入力し、従来の四隅・役割出力と全件一致した。
Android実機でのJNI動作確認は別途必要。
